# فريق Business Partner الذكي (Claude Managed Agents)

فريق موظفين أذكياء يعمل على مدار الساعة بدون الرجوع للمالك إلا للاعتماد.
المنسّق **باهر** (مستشار الأعمال) يستقبل كل شيء ويوزّعه على أربعة مدراء، كلٌّ في تخصصه.

| الوكيل | الدور | الموديل | متى يتدخل |
|---|---|---|---|
| **باهر** | المنسّق العام ومستشار الأعمال | Opus 5 | نقطة الدخول الوحيدة لأي طلب أو حدث أو جدولة |
| **مازن** | استقبال ومتابعة العملاء | Sonnet 5 | أي عميل من أي قناة (واتساب، إيميل، الموقع، سوشال) + المتابعة اليومية |
| **بدر** | المبيعات والعروض | Opus 5 | الفرص المؤهلة، مسودات العروض من الكتالوج بانتظار الموافقة |
| **فرح** | التسويق والمحتوى | Sonnet 5 | كل نص موجه لجمهور، وتجهيز محتوى الأسبوع |
| **محمد** | الموقع والتقنية | Opus 5 | فحص www.businesspartner.sa يوميًا، إصلاح، PR مسودة |

الملفات: `*.agent.yaml` تعريف كل وكيل، `prompts/*.md` تعليماته، `environment.yaml` بيئة التشغيل،
`deployments/*.yaml` الجدولات، `scripts/` أوامر الإنشاء والتشغيل، و`ids.env` معرّفات ما أُنشئ (يُرفع إلى git).

## كيف يعمل "24 ساعة"
لا يوجد موديل "صاحي" طول الوقت. الفريق يعمل بثلاث طرق، وبينها لا يستهلك شيئًا:

1. **جدولات** (`deployments/`): جولة متابعة العملاء ٠٦:٠٠، فحص الموقع ٠٧:٠٠، محتوى الأسبوع كل خميس ١٠:٠٠ بتوقيت الرياض.
   كل جولة تفتح جلسة لباهر بسقف ميزانية بالدولار.
2. **أحداث** عبر n8n: رسالة واتساب أو نموذج الموقع تصل إلى `baher-intake-v2` فتفتح جلسة فورًا، والوكيل يرد على العميل عبر `bp-agent-send`.
3. **أوامر مباشرة** من المالك: `npm run run -- "تابع العميل فلان..."`.

الذاكرة الدائمة في memory store باسم `bp-team` (تُركّب في `/mnt/memory/bp-team/`)، ومكتب الفريق هو نوشن (Sales Pipeline، Team Tasks، BP Proposals، تقويم المحتوى).

## الحوكمة المدمجة
- أي سعر نهائي أو عقد أو دفع أو إجراء حكومي = صف «بانتظار الموافقة» في نوشن، لا تنفيذ.
- الأسعار من الكتالوج الرسمي فقط. لا OTP ولا كلمات مرور.
- تغييرات الموقع = Pull Request مسودة فقط، لا دمج.
- الأسرار لا تدخل حاوية الوكيل أبدًا (خزنة Anthropic تحقنها عند الخروج من الشبكة).
- سقف إنفاق لكل جلسة وجدولة (`budget`)، ويمكن إيقاف أي جدولة بأمر واحد.

## خطوات البدء (مرة واحدة، نحو ساعة)

### 1. الحساب والمفتاح
- افتح [console.anthropic.com](https://console.anthropic.com)، اشحن رصيدًا (ابدأ بـ 50 دولار للتجربة)، وأنشئ API key.
- ثبّت الأداة `ant` (Linux/WSL):
  ```bash
  VERSION=<آخر إصدار من github.com/anthropics/anthropic-cli/releases>
  curl -fsSL "https://github.com/anthropics/anthropic-cli/releases/download/v${VERSION}/ant_${VERSION}_linux_amd64.tar.gz" | sudo tar -xz -C /usr/local/bin ant
  ```
  على macOS: `brew install anthropics/tap/ant`.
- انسخ `agents/.env.example` إلى `agents/.env` وضع `ANTHROPIC_API_KEY`.

### 2. أنشئ الفريق
```bash
cd agents
export $(grep -v '^#' .env | xargs)
npm run apply        # البيئة + الذاكرة + الوكلاء الخمسة → ids.env
```
أعد تشغيل الأمر نفسه بعد أي تعديل في `prompts/` أو `*.agent.yaml`: يحدّث الوكلاء في مكانهم (نسخة جديدة) بدل إنشاء وكلاء جدد.

### 3. الاعتمادات (الخزنة)
ضع في `agents/.env` ما يتوفر لديك ثم:
```bash
npm run vault
```
- `BP_N8N_HOOK_KEY`: مفتاح عشوائي طويل تختاره أنت، نفسه يوضع في n8n كاعتماد Header Auth باسم `X-BP-Agent-Key`.
- `GITHUB_TOKEN`: توكن دقيق الصلاحيات على `businessKSA/business-partner-sa` (Contents: Read/Write، Pull requests: Read/Write). يلزم لمحمد.
- Notion MCP: يحتاج OAuth لخادم `mcp.notion.com` (توكن تكامل `ntn_` لا يعمل هنا). أسهل طريق اليوم: من Console → Vaults أضف اعتماد Notion بتدفق OAuth من الواجهة، ثم ضع `VAULT_ID` في `.env`. بدونه يعمل الفريق لكن بلا نوشن.

### 4. جرّب
```bash
npm install
npm run run -- "عميل جديد اسمه أحمد، رقمه 9665xxxxxxxx، يبغى تأسيس شركة في الرياض. تابعه."
npm run run -- --site "افحص صفحة /contact بالعربية والإنجليزية وأصلح أي رابط مكسور"
```
يطبع رابط الجلسة في Console لتشاهد التوزيع والتقارير حيًا.

### 5. شغّل الجدولات
```bash
npm run schedule
```
لإيقاف واحدة مؤقتًا: `ant beta:deployments pause --deployment-id <id>`. لتعديل التوقيت: عدّل YAML ثم أعد الأمر.

### 6. اربط n8n
- استورد `ops/n8n/bp-agent-send.workflow.js` و`ops/n8n/baher-intake-v2.workflow.js`، واملأ المعرّفات في أعلى الملف الثاني من `ids.env` و`.env`.
- أنشئ الاعتمادين المذكورين في الملاحظة اللاصقة داخل كل سير، ثم وجّه `BP-WhatsApp-Main` إلى `/webhook/baher-intake-v2`.
- السيور القديمة (`baher-intake`، `badr-intake`، ...) تبقى كما هي حتى تتأكد من الجديد.

## الاستخدام اليومي
- المالك يرسل على واتساب أو يشغّل `npm run run`: "تابع فلان"، "جهّز عرض لشركة كذا"، "صفحة الأسعار فيها غلط".
- كل ما ينتظر قرارك يظهر في نوشن بحالة «بانتظار الموافقة» أو كـ PR مسودة في GitHub، وتصلك الخلاصة على واتساب.
- المتابعة: `ant beta:sessions list --transform '{id,title,status,usage.list_cost}' --format jsonl`.

## التكلفة التقريبية
سقوف الجدولات في YAML: 4 دولار للجولة الصباحية، 6 لفحص الموقع، 5 للمحتوى الأسبوعي، و3 لكل رسالة عميل. الحد الأعلى النظري نحو 300 دولار شهريًا مع 100 رسالة عميل؛ الفعلي عادة أقل لأن الجلسات تنتهي قبل السقف. عدّل `amount` في `deployments/*.yaml` و`SESSION_BUDGET_CENTS` في سير n8n.

## للمتابعة في جلسة Claude Code
الصق هذا في جلسة جديدة بعد تنفيذ الخطوة 1:

> اقرأ `agents/README.md` في المستودع. نفّذ خطوات البدء 2 إلى 5 بالترتيب باستخدام المفتاح في `agents/.env`، وأصلح أي خطأ يظهر من `ant` أو السكربتات. بعد نجاح `npm run run` بجلسة تجريبية، انشر سيري n8n في `ops/n8n/` (bp-agent-send ثم baher-intake-v2) بالمعرّفات من `ids.env`، وأخبرني بما يحتاج مني يدويًا (اعتماد Notion، WhatsApp، الرصيد).

## ما لم يُنجَز بعد
- اعتماد Notion MCP يحتاج تدفق OAuth من Console (لا يُنجز بسكربت).
- سيور n8n مكتوبة ومُتحقق منها لكن غير منشورة، لأنها تحتاج معرّفات الوكلاء ومفتاح Anthropic.
- قناة الإيميل في `bp-agent-send` (واتساب فقط الآن).

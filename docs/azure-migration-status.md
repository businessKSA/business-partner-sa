## 1) الصورة الحقيقية اليوم (ليست فكرة — هذا ما في الكود)

المشروع **هجين بالفعل**: الحوسبة على Vercel، والخدمات الثقيلة تتحول تدريجياً
إلى Azure. الذكاء الاصطناعي **انتقل بالكامل** إلى Azure.

| الطبقة | أين تعمل الآن | الحالة |
|---|---|---|
| الموقع + واجهات الـAPI (الحوسبة) | Vercel (مشروع واحد) | ✅ يعمل |
| الذكاء الاصطناعي (كل الوكلاء والدردشة) | **Azure OpenAI** (`api/_azure.js`) | ✅ مهاجَر بالكامل |
| قاعدة البيانات (الإنتاج) | Supabase (عبر `api/_db.js`) | ✅ يعمل / ⚠️ لم يُحوَّل لـAzure بعد |
| قاعدة بيانات Azure (بديل جاهز) | `api/_azpg.js` مكتوب لكنه **غير موصول** بـ`sb()` | 🟡 كود جاهز، غير مفعّل |
| تخزين ملفات العملاء | Azure Blob إن ضُبط المفتاح، وإلا Supabase Storage | ✅ يتحول بمتغيّر بيئة واحد |
| الإشعارات / البريد | Microsoft Graph (`api/_msgraph.js`) + `_azure_notify.js` | ✅ مسار Azure جاهز |
| الأتمتة (n8n / واتساب) | ملفات workflow + Logic App JSON (`ops/azure/`) | 🟡 معرّفة، تشغيلها 24/7 غير مؤكد |
| المدفوعات (Moyasar / Tamara / BNPL) | خدمات خارجية سعودية | ❌ تبقى خارجية (لا تُنقل) |
| التكاملات الحكومية (نفاذ / اعتماد / قوى / ZATCA) | منصات حكومية | ❌ تبقى خارجية (لا تُنقل) |

**الخلاصة:** أهم وأخطر طبقة (الذكاء الاصطناعي) **تمت هجرتها**. الباقي إما جاهز
بمتغيّر بيئة، أو يحتاج ربطاً بسيطاً، أو يبقى خارج Azure لأنه خدمة خارجية.

## 2) القرار المعماري: هجين، وليس نقلاً كاملاً

**التوصية المعتمدة:** لا ننقل *كل* شيء إلى Azure. ننقل ما يستفيد فعلاً من
التشغيل الدائم والمنحة، ونُبقي الحوسبة الخفيفة على Vercel لأنها تعمل ومجانية.

| الجزء | الأفضل له | السبب المبسّط |
|---|---|---|
| الموقع | Vercel (الحالي) | يعمل، سريع، شبه مجاني، لا داعي لتحريكه الآن |
| واجهات الـAPI | Vercel (الحالي) | مربوطة بالموقع؛ نقلها لاحقاً فقط إن لزم |
| قاعدة البيانات | **Azure** (Postgres) | تعمل 24/7، والمنحة تغطيها، وبيانات العملاء أهم أصل |
| التخزين | **Azure** (Blob) | ملفات دائمة، جاهزة بالفعل بمتغيّر واحد |
| الذكاء الاصطناعي | **Azure** ✅ تم | مزوّد واحد ثابت = لا انقطاع بسبب رصيد مزوّد آخر |
| الأتمتة / n8n | **Azure** (Container Apps) | تحتاج تشغيلاً دائماً؛ المنحة أنسب من جهاز محلي |
| العمّال والطوابير (Workers/Queue) | **Azure** (Service Bus + Container Apps) | أساس تشغيل الوكلاء 24/7 |
| السكربتات المؤقتة / التطوير | محلي (Local) + Terminal | لا تحتاج سحابة |

## 3) لماذا لا يمكن «الضغط على زر Azure» من هذه الجلسة

- لا يوجد اتصال Azure (لا مفاتيح ولا أداة Azure) داخل هذه الجلسة، فلا أستطيع
  إنشاء موارد Azure أو نشرها من هنا. أستطيع تجهيز **الكود** فقط.
- تفعيل مسارات Azure الجاهزة يتم بضبط **متغيّرات البيئة في Vercel** (أسرار
  يملكها المالك)، مثل: `AZURE_PG_URL`, `AZURE_STORAGE_ACCOUNT`,
  `AZURE_STORAGE_KEY`, ومفاتيح `AZURE_OPENAI_*`.
- لذلك التنفيذ الفعلي على Azure = خطوة يقوم بها المالك (أو جلسة لديها وصول
  Azure)، ودوري تجهيز كل شيء ليعمل بمجرد لصق المفاتيح.

## 4) الهجرة بلا توقف (Zero-Downtime) — الترتيب الآمن

نتبع مبدأ: نبني الجديد بجانب القديم، ننسخ، نختبر، نحوّل تدريجياً، ونُبقي خطة رجوع.

1. **قاعدة البيانات:** إنشاء Azure Postgres → نسخ بيانات Supabase → ضبط
   `AZURE_PG_URL` → وصل `_azpg.js` بـ`sb()` خلف مفتاح تشغيل → اختبار قراءة/كتابة
   → تحويل. القديم (Supabase) يبقى للرجوع حتى التأكد.
2. **التخزين:** ضبط مفاتيح Azure Blob → نسخ الملفات → التحويل يتم تلقائياً
   لأن `_db.js` يفضّل Blob عند توفّر المفتاح.
3. **الأتمتة/n8n:** تشغيل على Azure Container Apps → اختبار → تحويل.
4. **الحوسبة (الموقع/الـAPI):** آخر ما يُنقل، وفقط إن دعت الحاجة.

## 5) طبقة التشغيل الدائم (لتحقيق «أنا أعطي الهدف فقط»)

رؤية «المدير التنفيذي الذكي + الإدارات + الوكلاء» **غير مبنية بعد** (🔵 مخطط).
بناؤها الصحيح يحتاج بنية Azure دائمة، وليست محادثة مفتوحة:

```
Baher → Executive AI Manager → Orchestrator → Department Managers → Agents
                                     ↓
   Azure Service Bus (طابور)  +  Azure Container Apps (عمّال دائمون)
   Azure Postgres (ذاكرة/سجلات)  +  Azure Key Vault (أسرار)  +  Azure Monitor (مراقبة)
```

لا يُبنى أي وكيل أو مدير جديد إلا عند حاجة تشغيلية فعلية (قاعدة Agent Factory).

## 7) أخطاء مرصودة (ERRORS FOUND)

1. **اختبار مزوّد قديم** — `tests/azure-provider.test.mjs:97` يتوقّع مزوّد
   `gemini` بعد أن أُزيل عمداً (المشروع الآن Azure فقط). الاختبار قديم، ليس
   عطلاً في الإنتاج. الإصلاح: تحديث الاختبار ليعكس «لا مزوّد غير Azure».
   الحالة: مرصود، بانتظار مراجعة آمنة.
2. **اختبار عقد قانوني** — `tests/contract.test.mjs` يفشل في ترقيم بنود العقد
   العربي (أولاً…عاشراً). لأنه يمسّ **نصاً قانونياً**، لا يُصلَح تلقائياً؛
   يحتاج قرار المالك. الحالة: مرصود، مُصعّد (🔴).
3. **فجوة وصل Azure Postgres** — `_azpg.js` مكتوب لكن `sb()` في `_db.js` لا
   يستدعيه؛ أي أن قاعدة بيانات Azure لن تُستخدم حتى لو ضُبط `AZURE_PG_URL`.
   الإصلاح مخطّط في البند 2 من قائمة العمل أعلاه.

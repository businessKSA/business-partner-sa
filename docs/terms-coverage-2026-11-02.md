## قواعد الصياغة التي التُزم بها

- **لا مادة نظامية ولا رقم مادة ولا سابقة**: ذُكرت الأنظمة بأسمائها فقط. الاختبار يمنع نمط «المادة N» / «Article N».
- **لا رقم رسم حكومي ولا مدة حكومية**: كل رسم «يحدده الجهة المختصة»، والكتالوج وحده يقول «الرسوم الحكومية منفصلة».
- **لا وعد بنتيجة حكومية**: القبول والإصدار والتجديد والإلغاء قرار الجهة؛ والتزامنا بذل العناية المهنية.
- **المخالفات**: مراجعة ← دراسة أهلية الاعتراض ← تجهيز ← تقديم ← متابعة، ولا وعد بإلغاء مخالفة أو خفضها.
- **التمثيل والتقاضي والتوقيع**: خارج الخدمات العادية؛ يلزمه وكالة نظامية ومرخَّص بعقد مستقل ولا يوقّع أحد نيابةً عن أحد دون تفويض موثَّق.
- **الاسترجاع بمبادئ بلا أرقام** (انظر القرارات أدناه).

## واجهة الموافقة لوكيل السلة (`site/scripts/terms-gate.mjs`)

لا تعدّل cart/checkout هنا؛ هذه الواجهة تُسلَّم لوكيل `cart-checkout` ليربطها. الاستعمال كاملاً في رأس الملف.

```js
// الخادم/البناء
import { loadTermsData, termsForSku, termsForCart } from './terms-gate.mjs';
const data = loadTermsData();
termsForSku(data, 'svc-bp-sbc-01', 'ar');
// → { matched, sku:'BP-SBC-01', category:'formation', categoryTitle, url:'/ar/terms#cat-formation',
//     generalUrl:'/ar/terms#general', consentText:'أقرّ بأنني اطّلعت على الشروط العامة وشروط فئة «…» وأوافق عليها.', version }
termsForCart(data, cartItems, 'ar');
// → { categories:[{id,title,url,skus}], unmatched:[], consentText (تسمّي كل الفئات)، generalUrl, version }
```

```js
// المتصفح (السلة/الدفع): حقن نصّ البوابة مرة، ثم تحميل الفهرس الخفيف
// <script>${termsGateClientSource()}</script>
BPTermsGate.load('/assets/data/terms-index.json').then(function (idx) {
  var r = BPTermsGate.termsForCart(idx, JSON.parse(localStorage.bp_cart || '[]'), 'ar');
  // r.consentText → نصّ خانة الإقرار · r.categories[i].url → رابط «اقرأ الشروط»
});
```

- يقبل معرّفات السلة الفعلية: `svc-<sku>` · `pkg-<مفتاح>` · رمز الرحلة · `employee-*` · `agent-compliance` · `agent-shared-services` · `employer-plan-*` · `companies-data-access` · `revos-*`.
- مجهول → `matched:false` ويحمل الشروط العامة وحدها (`/terms#general`)، لا يرمي خطأ.
- `terms-index.json` (≈13KB) يُولَّد بالبناء من terms.json، فلا يُحرَّر باليد.
- **ما على وكيل السلة**: (أ) استبدال الرابط الواحد `/terms` في خانة إقرار الدفع بجملة `consentText` ورابط كل فئة؛ (ب) تخزين `version` والفئات مع الطلب؛ (ج) صفحة الخدمة (`simple-v1-service-detail`) يمكنها عرض رابط `termsForSku(...).url` — ملفها لوكيل الكتالوج لا لي.

## ما لم أمسّه

- `site/scripts/simple-v1-cart.mjs` و`simple-v1-checkout.mjs` (cart-checkout). `privacy` و`data-deletion` (يملكهما غيري) — الشروط تحيل إليهما بالرابط فقط.
- `site/data/site.json` (نص `terms` القديم باقٍ كما هو لتعتمد عليه `buildTerms()` في وضع `SIMPLE_V1=0` فقط، ولا يُبنى به شيء في الوضع الحالي). يُحذف حين يُغلق الموقع القديم.
- ميزات الباقات في الكتالوج (ادعاء «فلا تصلك غرامات»): يملكها catalog-content.
- `generate.mjs`: سطور محدودة فقط (استيراد + ثلاثة مواضع)، وهو ملف platform-engineer؛ ذُكر هنا للشفافية.

## إضافة خدمة جديدة

1. أضف الـSKU إلى `skus` في `site/assets/data/terms.json` (أو يكفي بادئة موجودة في `prefixRules`).
2. `npm run build` (يُعيد توليد `/terms` و`terms-index.json`) ثم `node --test tests/terms-coverage.test.mjs`.
3. فئة جديدة؟ أضفها بالعربية والإنجليزية والفرنسية والصينية، وإلا فشل الاختبار.

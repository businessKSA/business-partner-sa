# تحضير اجتماع المستشار التقني — منشآت · وكيل الامتثال (Business Partner)
### ورقة قيادة الاجتماع · اليوم 3 العصر

> الهدف: إقناع مستشار تقني محترف بأن المشروع **حقيقي ومبنيّ وقابل للتنفيذ وممتثل**. القاعدة الذهبية: **قُد بالنموذج المتوافق القابل للعرض اليوم، واعرض التنفيذ الآلي الكامل كخارطة طريق مشروطة بتكامل رسمي.**

---

## 1) الرسالة المحورية (30 ثانية)
> «وكيل الامتثال من Business Partner يمثّل خبرة باهر (20+ سنة في الخدمات الحكومية وإدارة المنصات) كوكيل ذكاء اصطناعي يعمل عبر واتساب: **يراقب** حالة المنشأة على قوى ومقيم والتأمينات والمركز السعودي للأعمال، **ينبّه** قبل الانتهاءات والمخالفات، **يجهّز كل إجراء كاملًا** (الموظفون، النوع، الرسوم، النماذج)، **وينفّذه ضمن جلسة يعتمدها المالك** — مع سجل تدقيق كامل. المنشأة تحصل على فريق امتثال كامل باشتراك شهري بدل توظيف طاقم.»

الفرق الذي يميّزنا: **لسنا شات معلومات، ولا مكتب خدمات يدوي** — نحن طبقة تشغيل استباقية متعددة المنصات مبنية فعليًا.

---

## 2) المعمارية التقنية (اعرضها كدليل أن المشروع مبنيّ لا موعود)
```
واتساب / الموقع / البريد   ← طبقة العميل (محادثة طبيعية)
        │
      n8n                  ← التنسيق: توجيه، جدولة، سجل تنفيذ (workflows حيّة)
        │
   Claude (sonnet)         ← الاستدلال: فهم الطلب، تجهيز الإجراء، صياغة التنبيه
        │
     Notion                ← العقل/مصدر الحقيقة: سجل الامتثال، الأدلة، سجل التدقيق، بوابة الموافقات
        │
   محرك القواعد            ← rules-engine.json: قوى/مقيم/التأمينات/مدد/الزكاة/بلدي… + النطاقات + الرسوم
```
**أصول حقيقية جاهزة للعرض (ليست شرائح):**
- وكيل امتثال يومي حيّ على n8n (تقييم + تقرير 07:00) + وكيل محادثة حيّ.
- سجل الامتثال + سجل تدقيق + بوابة موافقات في Notion.
- محرّك قواعد + حاسبات نطاقات والرسوم (قابلة للاستدعاء).
- مكتبة مراجع حكومية (83 ملفًا رسميًا من HRSD) + مرجع قرارات السعودة.
- بنية معيارية: **إضافة منصة = صفّ في محرك القواعد، بلا تعديل كود.**

---

## 3) النقطة الحرجة — كيف ندخل المنصات الحكومية؟ (اربح هنا)
هذا **أهم سؤال** وسيُطرح. جوابك المعتمد:

> «**لا نطلب ولا نخزّن كلمات مرور أو رموز نفاذ (OTP) إطلاقًا.** المنصات الحكومية تحجب الأتمتة غير المصرّح بها، ونحن نحترم ذلك. نموذجنا الحالي (V1) هو **تنفيذ مُوجَّه بموافقة (Assisted Execution)**:
> 1. الوكيل يجمع الطلب عبر واتساب: *«عندك هؤلاء الموظفين — مين تبغى تجدد له؟ وش الإجراء؟»*.
> 2. يجهّز كل شيء آليًا: القائمة، نوع الإجراء، الرسوم، النموذج، والخطوات.
> 3. **التنفيذ يتم ضمن جلسة يبدأها المالك ويعتمد فيها كل إجراء حسّاس** — التفويض والدخول بيده، والوكيل يوفّر عليه الجهد والوقت والخطأ.
> 4. **كل خطوة مسجّلة في سجل تدقيق** (من؟ متى؟ ماذا؟).
> أما **التنفيذ الآلي الكامل عبر المنصات** فهو مسارنا التالي (V2) عبر **تكامل رسمي / Sandbox** مع الجهات — وهذا بالضبط ما نطلب دعم منشآت فيه.»

**لماذا هذا يقنع:** يظهر أنك تفهم القيود القانونية والتقنية (نفاذ، حجب الأتمتة، PDPL)، وأن عندك مسارًا متوافقًا يعمل الآن، وخطة واقعية للأتمتة الكاملة. المستشار يثق بمن يعرف الخطوط الحمراء، لا بمن يتجاهلها.

> ⚠️ **تجنّب تمامًا** عبارة «ناخذ كود الدخول من العميل وننفّذ بدون تدخل بشري». استبدلها بـ«العميل يعتمد ويفوّض، والوكيل يجهّز وينفّذ الخطوات الروتينية ضمن جلسته». نفس تجربة العميل تقريبًا، لكن متوافقة وقابلة للدفاع.

## 4) نموذج التنفيذ المتدرّج (اعرضه كخارطة)
| المرحلة | كيف ينفَّذ | الحوكمة | جاهز؟ |
|---|---|---|---|
| **V1 — تنفيذ مُوجَّه (اليوم)** | الوكيل يجهّز ويوجّه؛ المالك يعتمد الإجراء الحسّاس؛ تنفيذ Concierge هجين | موافقة بشرية + سجل تدقيق + بلا OTP مخزّن | ✅ مبنيّ |
| **V2 — تكامل رسمي** | APIs مصرّح بها (التأمينات/علم-مقيم، الزكاة/فاتورة، قوى) عبر شراكة/Sandbox | نفس بوابة الموافقة + تفويض موثّق | 🔜 الطلب من منشآت |
| **V3 — أتمتة موسّعة** | تنفيذ آلي للإجراءات المصرّح بها، ومزامنة دورية | صلاحيات دقيقة + مراجعة استثناءات | خارطة |

النطاق المبدئي (MVP): **قوى + مقيم** (تجديد إقامات، نقل خدمات/كفالة، خروج وعودة/نهائي، إضافة موظفين، توثيق عقود، متابعة التوطين) — الأعلى تكرارًا والأعلى خطورة عند التأخير.

---

## 5) العرض الحي (Demo — لا تعرض ما لم تختبره)
1. **محادثة واتساب/الشات الحيّة** مع وكيل الامتثال: اسأله عن حالة منشأة أو إجراء.
2. **سجل الامتثال + سجل التدقيق في Notion**: أظهر كيف يُسجّل كل تنبيه وقرار.
3. **حاسبة النطاقات + الرسوم**: نتيجة فورية بمصدر.
4. **تقرير الامتثال اليومي** (نموذج AR/EN).
> رسالة الديمو: «هذي ليست فكرة — هذا نظام يعمل، وينقصه التكامل الرسمي والتوسّع.»

## 6) الأسئلة الصعبة وإجاباتها الجاهزة
| السؤال | الإجابة |
|---|---|
| **هل عندكم API رسمي مع قوى/مقيم؟** | ليس بعد لكل منصة؛ لدينا أساس تكامل التأمينات (GOSI) مبنيّ، والباقي عبر شراكة/Sandbox. حتى ذلك الحين V1 تنفيذ مُوجَّه بموافقة — يعمل اليوم. |
| **ألا يخالف دخول المنصة بحساب العميل الأنظمة؟** | لهذا لا نخزّن بيانات دخول ولا OTP، والتفويض والدخول يبدآن من المالك. الأتمتة الكاملة فقط عبر مسار رسمي. |
| **كيف تحمون البيانات (PDPL)؟** | أقل صلاحية، تشفير الأسرار في n8n (لا في الشات/الكود)، موافقة على الإجراءات الحسّاسة، سجل تدقيق، وسياسة خصوصية. |
| **هل هذا مجرد Chatbot؟** | لا — الواجهة شات، خلفها محرّك قواعد + سجل امتثال + workflows + بوابة موافقات + تنفيذ مُدار. |
| **ما ميزتكم أمام مكتب خدمات أو HRMS؟** | مراقبة استباقية متعددة المنصات + معرفة سعودية منظّمة + سجل تنفيذ — نُكمّل الأنظمة لا نستبدلها. |
| **لماذا أنت بالذات؟** | 20+ سنة خبرة تشغيلية عشت فيها المشكلة، وبنيت النظام والبيانات والأتمتة حولها (Founder-market fit). |
| **ما حجم التمويل المطلوب؟** | لا نطرح رقمًا اليوم؛ نقفل نموذجًا ماليًا من أسفل لأعلى بعد تجربة مدفوعة، ونعود برقم موثّق واستخدامات واضحة. |

## 7) الطلب من منشآت (اجعل المستشار حليفًا)
اطلب **شيئًا واحدًا واضحًا يزيل خطرًا**:
1. **الأهم:** مسار/تعريف رسمي للتكامل أو Sandbox مع الجهات (التأمينات، علم/مقيم، قوى، المركز السعودي للأعمال، الزكاة) — لأنه مفتاح الأتمتة الكاملة.
2. احتضان + إرشاد تقني في الحوكمة والأمن.
3. الوصول إلى **10–50 منشأة** كعملاء تجربة (Design Partners) لإثبات القيمة خلال 90 يومًا.

**جملة الإغلاق:**
> «لا أطلب اليوم أن تصدّق الحلم الكامل. أطلب أن نتفق: هل مشكلة الامتثال تستحق تجربة 90 يومًا؟ وإذا نعم، هل تفتح لنا باب التكامل الرسمي أو تجربة معتمدة؟»

## 8) ملخص «لا تفعل / افعل»
- ❌ لا تقل: «ناخذ كود الدخول وننفّذ كل شي بدون تدخل بشري».
- ✅ قل: «العميل يعتمد ويفوّض، والوكيل يجهّز وينفّذ الروتين ضمن جلسته، بسجل تدقيق، والأتمتة الكاملة عبر تكامل رسمي».
- ❌ لا تعِد بأرقام تمويل أو إيراد نهائية.
- ✅ اعرض أصولًا حقيقية (n8n/Notion/الحاسبات) وخارطة متدرجة.
- ✅ حوّل سؤال «الصلاحيات» إلى «طلبك من منشآت».

# نقل n8n من سحابة n8n إلى Azure — الخطة التنفيذية

**القرار (المالك، 2026-09-29):** الطريق الأول — ننقل **n8n نفسه** إلى خوادم Azure،
ولا نعيد بناء السيرَات في Logic Apps. الـ١٠٧ سير تنتقل كما هي.

**الهدف الحقيقي:** الفاتورة تنتقل على منحة Azure ($100,000) بدل اشتراك سحابة n8n،
بدون إعادة كتابة سطر واحد وبدون مخاطرة على خدمات تعمل.

---

## 1) المعمارية المستهدفة

| المكوّن | الخدمة على Azure | الحجم |
|---|---|---|
| تطبيق n8n | Azure Container Apps | 1 vCPU / 2 GB، نسخة واحدة دائمة |
| قاعدة البيانات | Azure Database for PostgreSQL Flexible Server | Burstable B1ms، 32 GB |
| الملفات الثابتة | Azure Files (مرتبط على `/home/node/.n8n`) | 10 GB |
| النطاق | `n8n.businesspartner.sa` + شهادة مُدارة | — |

**المنطقة: Sweden Central** — نفس منطقة `bp-ai-ksa-2026`. هذا مقصود: كل نداءات
Azure OpenAI تبقى داخل نفس مركز البيانات، فالاستجابة أسرع ولا توجد رسوم خروج بيانات.

**مهم — لا تُفعّل «التصغير إلى صفر» (scale to zero).** n8n يستقبل ويبهوكس من واتساب
والموقع، ويشغّل ١٢ مهمة مجدولة. النسخة الدنيا لازم تبقى **1** دائماً.

### التكلفة التقديرية (من المنحة)

| البند | شهرياً |
|---|---|
| Container App (1 vCPU / 2 GB دائم) | ‏$35–45 |
| PostgreSQL B1ms + 32 GB | ‏$15–20 |
| Azure Files 10 GB | ‏$1 |
| **الإجمالي** | **‏$55–70 شهرياً** (≈ $800 سنوياً من المنحة) |

## 3) المخاطر الأربعة الحقيقية

### ٣-١ الاعتمادات لا تنتقل — إطلاقاً
n8n يشفّر الاعتمادات بمفتاح `N8N_ENCRYPTION_KEY`، وسحابة n8n **لا تعرض هذا المفتاح**.
يعني: الـ٣٤ اعتماداً كلها تُدخَل من جديد بيدك.

منها **١٢ اعتماد OAuth** تحتاج إعادة تفويض من المتصفح (تسجيل دخول فعلي):

| الاعتماد | النوع |
|---|---|
| Gmail OAuth2 API · Gmail — Business Partner · Gmail — Farina · Gmail account 2 | OAuth |
| Google Drive OAuth2 API | OAuth |
| Google Calendar — Business Partner | OAuth |
| Notion — Business Partner OS · Notion account · Notion MCP OAuth2 | OAuth |
| LinkedIn account · LinkedIn — Baher Magnas | OAuth |
| Outlook — Business Partner | OAuth |
| GitHub — Business Partner | OAuth |

والباقي (واتساب ×٦، Azure OpenAI، OpenAI، Anthropic، Gemini، OpenRouter، ElevenLabs،
Daftra، Vercel، Header Auth ×٤) مفاتيح نصية — تُلصَق لصقاً، لكن **تحتاج تكون عندك**.

> **قبل أن نبدأ:** تأكد أن كل مفتاح API لديك محفوظ في مكان آمن. إذا ضاع مفتاح، تحتاج
> تولّده من جديد من موقع المزوّد. لا تكتب أي مفتاح في المحادثة.

### ٣-٢ جداول البيانات تحمل بياناتك الحية
نظام التشغيل الذكي كله يقرأ ويكتب في ٩ جداول:

| الجدول | ما فيه |
|---|---|
| `BP_AI_Tasks` | مهام الفريق الذكي كلها |
| `BP_AI_Deals` | **الصفقات: القيمة، حالة الدفع، حالة العقد، المحصّل** |
| `BP_AI_Finance_Ledger` | القيود المالية |
| `BP_Agent_Registry` | سجل الـ٢٢ وكيلاً وحالتهم |
| `BP_AI_Performance` | مؤشرات الأداء اليومية |
| `BP_AI_Growth_Campaigns` | الحملات |
| `BP_AI_Integration_Readiness` | جاهزية التكاملات |
| `BP_AI_Departments` | هيكل الأقسام |
| `BP_AI_Control_Commands` | أوامر لوحة التحكم |

ما فيه زر «تصدير» لهذه الجداول. السكربت `ops/azure/02-copy-data-tables.mjs` ينسخها
صفاً صفاً عبر الـAPI. **لازم توقف الكتابة أثناء النسخ** وإلا تضيع صفوف كُتبت في
المنتصف.

(جدول عاشر اسمه `BP_HEALTH_RESULT_queued_R0_...` بقايا اختبار قديم — لا يُنقل.)

### ٣-٣ مشروع الفريق ميزة مدفوعة
عندك مشروع فريق اسمه `Business partner whatsapp` يحمل ٣ اعتمادات. في n8n المستضاف
ذاتياً، **مشاريع الفرق ميزة Enterprise مدفوعة**. على النسخة المجانية يوجد مشروع
شخصي واحد فقط.

الأثر: الاعتمادات الثلاثة تنتقل للمشروع الشخصي. يشتغل عادي، لكن تفقد الفصل
التنظيمي. إذا تبيه، يحتاج ترخيص Enterprise (تكلفة إضافية خارج المنحة).

### ٣-٤ التحويل لازم يكون قطعاً، لا تشغيلاً متوازياً
١٢ سيراً مجدولاً تكتب في نوشن، وترسل واتساب، وتنشئ صفقات. **إذا اشتغلت النسختان
معاً ولو ساعة:** رسائل واتساب مكررة لعملاء حقيقيين، صفقات مكررة، قيود مالية مكررة.

النسخة القديمة تُعطَّل في نفس اللحظة التي تُفعَّل فيها الجديدة. لا تداخل.

## 4) ترتيب التنفيذ

### المرحلة ٠ — التحضير (لا تحتاج Azure) · ساعة
- [ ] تصدير الـ١٠٧ سير: n8n → Workflows → تحديد الكل → **Download**
- [ ] حفظ الملف في `ops/n8n-export/`
- [ ] حصر كل رابط ويبهوك مستخدم خارجياً (واتساب، الموقع، محفول، اللوحات)
- [ ] تجهيز مفاتيح الـAPI الـ٢٢ في مكان آمن

### المرحلة ١ — بناء البنية على Azure · ساعة
```bash
bash ops/azure/01-provision.sh
```
ينشئ: مجموعة الموارد، PostgreSQL، Container Apps Environment، Azure Files،
تطبيق n8n، والنطاق. يطبع رابط n8n الجديد في النهاية.

### المرحلة ٢ — استعادة السيرَات والاعتمادات · ٣ ساعات (يدك)
- [ ] استيراد ملف السيرَات في n8n الجديد — **كلها تبقى معطّلة (Inactive)**
- [ ] إدخال الـ٣٤ اعتماداً بنفس **الأسماء بالحرف** (الأسماء هي ما يربط السير بالاعتمادات)
- [ ] إعادة تفويض الـ١٢ اعتماد OAuth

### المرحلة ٣ — نسخ جداول البيانات والتحقق · ساعة
```bash
node ops/azure/02-copy-data-tables.mjs --dry-run   # عدّ الصفوف أولاً
node ops/azure/02-copy-data-tables.mjs             # النسخ الفعلي
```
- [ ] مطابقة عدد الصفوف في الجدولين القديم والجديد
- [ ] تشغيل تجريبي لثلاثة سيرَات قراءة فقط (لا ترسل شيئاً)

### المرحلة ٤ — التحويل · ساعتان · **ليلة الجمعة، أقل وقت حركة**
الترتيب صارم:
1. تعطيل كل السيرَات في n8n القديم (تبقى موجودة، معطّلة فقط)
2. إعادة نسخ جداول البيانات (لالتقاط ما كُتب منذ المرحلة ٣)
3. تفعيل السيرَات في n8n الجديد
4. تحديث روابط الويبهوك في: واتساب Cloud API، `vercel.json`، صفحة محفول، لوحات ai-space
5. اختبار حي: رسالة واتساب واحدة، طلب واحد من الموقع، شات محفول واحد

### المرحلة ٥ — المراقبة · ٧ أيام
- [ ] مراجعة سجل التنفيذات يومياً
- [ ] إبقاء n8n القديم **معطّلاً لا محذوفاً** طوال الأسبوع (خطة التراجع)
- [ ] بعد ٧ أيام نظيفة: إلغاء اشتراك سحابة n8n

## 5) خطة التراجع

في أي لحظة خلال الأسبوع الأول:
1. تعطيل السيرَات في n8n الجديد
2. إرجاع روابط الويبهوك إلى `businesspartnerai.app.n8n.cloud`
3. تفعيل السيرَات في n8n القديم

مدة التراجع: **أقل من ١٥ دقيقة**. لهذا لا يُلغى اشتراك السحابة قبل أسبوع.

## 6) حالة الوصول إلى Azure — ابدأ من هنا

**آخر تحديث: 2026-09-29 · التحضير مكتمل، البناء لم يبدأ.**

| البند | الحالة |
|---|---|
| وصول الشبكة | ✅ مفتوح (Network access = `Full`) |
| `management.azure.com` | ✅ يستجيب |
| أداة `az` | ✅ تُثبَّت من Setup script |
| حساب الخدمة (Service Principal) | ✅ أُنشئ باسم `claude-code`، صلاحية Contributor على الاشتراك |
| بيانات الدخول | ✅ في **API credentials** بالبيئة السحابية |

### ما تقرؤه الجلسة من البيئة

| المتغيّر | المحتوى |
|---|---|
| `AZURE_CLIENT_ID` | معرّف حساب الخدمة |
| `AZURE_TENANT_ID` | معرّف الدليل |
| `AZURE_SUBSCRIPTION_ID` | معرّف الاشتراك |
| `AZURE_CLIENT_SECRET` | سرّ حساب الخدمة |
| `N8N_SRC_URL` · `N8N_SRC_KEY` | سحابة n8n المصدر |

**القيم نفسها ليست في هذا المستودع ولا تُكتب فيه** — تُقرأ من البيئة وقت التشغيل.

### أول أمر في الجلسة الجديدة

```bash
az login --service-principal \
  -u "$AZURE_CLIENT_ID" -p "$AZURE_CLIENT_SECRET" --tenant "$AZURE_TENANT_ID"
az account set --subscription "$AZURE_SUBSCRIPTION_ID"
az account show -o table
```

نجح؟ ابدأ المرحلة ٠ ثم ١.

### ملاحظات من محاولات سابقة (لا تعدها)

- **`az login` التفاعلي لا يعمل على هذا الحساب.** حساب Microsoft شخصي على «Default
  Directory»؛ الدخول ينجح ثم يرد «You don't have access to this». جُرّب ثلاث مرات
  بثلاث صيغ. حساب الخدمة هو الطريق، لا البديل المؤقت.
- **تركيب `az` عبر `aka.ms/InstallAzureCLIDeb` يفشل.** مستودعان مكسوران في الصورة
  (`deadsnakes` و`ondrej/php`) يُسقطان `apt-get update` كله. البديل المعتمد في
  Setup script هو venv:
  ```bash
  python3 -m venv /opt/azcli-venv && /opt/azcli-venv/bin/pip install -q azure-cli \
    && sudo ln -sf /opt/azcli-venv/bin/az /usr/local/bin/az
  ```
- **تغييرات البيئة تسري على الجلسات الجديدة فقط** — جلسة شغّالة لا تلتقطها.

## 7) ما لا ينتقل ولا يتغيّر

- **Azure OpenAI `bp-main`** — هو أصلاً على Azure. يبقى كما هو، ولا يتأثر بالنقل.
- **Vercel** — الموقع يبقى على Vercel. النقل يخص n8n فقط.
- **Notion · Google Drive · واتساب** — أنظمة خارجية، تبقى كما هي.

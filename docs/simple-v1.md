# Simple V1 — الطبقة المبسّطة للعميل (2026-09)

نسخة مبسطة فوق البنية القائمة: صفحة رئيسية تبيع ثلاث خدمات عبر محادثة واحدة،
بوابة عميل `/my`، ولوحة عمليات `/ops`. لا تحذف شيئاً من الموقع القديم؛ كل
المسارات القديمة تُولَّد كما هي.

## الخريطة

| الطبقة | الملف | ملاحظات |
|---|---|---|
| الرئيسية الجديدة (ar/en/fr/zh) | `site/scripts/simple-v1.mjs` | تُكتب في `/simple-v1` دائماً، وتحل محل `/` عند `SIMPLE_V1=1` (القديمة تنتقل إلى `/classic-home`) |
| بوابة العميل | `site/scripts/simple-v1-my.mjs` → `/my`, `/ar/my`, `/fr/my`, `/zh/my` | تعرض من `/api/simple` + `/api/otp` |
| لوحة العمليات | `site/scripts/simple-v1-ops.mjs` → `/ops` | عربية، مفتاح `PANEL_KEY` (أو `test-ops` في المعاينة) |
| محرك الطلب | `api/_simple.js` عبر `/api/simple` (rewrite إلى `requests?__route=simple`) | لا دالة جديدة على Vercel |
| المحادثة الموحّدة | `api/chat.js` وضع `mode:"intake"` | تُخرج كتلة `<<SCOPE>>…<<END>>` تتحول إلى نطاق قابل للتعديل |
| الدفع | `api/pay.js` بند `sv1:<ref>` | يُسعَّر من عرض الطلب على الخادم ويُعلَّم الطلب مدفوعاً بعد التحقق |
| قاعدة البيانات | `db/schema.sql` جداول `requests`, `request_events` + أعمدة على `tasks` | Supabase |

## المعاملة الواحدة

`NEW → REVIEWING → WAITING_CLIENT → QUOTE_SENT → QUOTE_APPROVED → CONTRACT_SENT → SIGNED → PAYMENT_PENDING → PAID → IN_PROGRESS → COMPLETED` (+ `CANCELLED`).
العرض والعقد والدفع والفاتورة والموعد لقطات JSON على صف الطلب نفسه.

## ما أُعيد استخدامه كما هو
الجلسات والدخول (`api/otp.js`)، `getSession/sb/audit/notify` (`api/_db.js`)، قالب العقد (`api/_docusign.js contractHtml`)، الكتالوج (`api/_catalog.js`)، السلة `bp_cart` وصفحة `/checkout` وميسر وتمارا (`api/pay.js`, `api/_bnpl.js`)، حجز الاستشارة (`api/book.js`)، جدول المهام والتذاكر والمنشآت، الشعار والخط والألوان.

## متغيرات البيئة الخاصة بالنسخة
| المتغير | الأثر |
|---|---|
| `SIMPLE_V1=1` | (بناء) الرئيسية الجديدة تحل محل `/` |
| `SIMPLE_TEST_MODE=1` أو `VERCEL_ENV=preview` | وضع الاختبار: توقيع داخل البوابة، دفع محاكى، فاتورة اختبار، دخول تجريبي |
| `SIMPLE_OPS_KEY` | مفتاح `/ops` في وضع الاختبار (الافتراضي `test-ops`) |
| `SIMPLE_TEST_OTP` | رمز الدخول الثابت لعناوين `@test.businesspartner.sa` (الافتراضي `123456`) |
| `SIMPLE_NOTIFY=1` | يسمح بإرسال بريد فعلي للعملاء والمالك؛ بدونه لا تُرسل رسائل |

## حسابات الاختبار (وضع الاختبار فقط)
- عميل: أي بريد بنطاق `@test.businesspartner.sa` والرمز `123456`.
- لوحة العمليات: المفتاح `test-ops` (أو `PANEL_KEY` الحقيقي).

## التشغيل محلياً
`npm run build` ثم خادم ساكن على `site/`. للتجربة بلا قاعدة بيانات: خادم المحاكاة في مجلد سكراتش الجلسة (`mockserver.mjs`) يحاكي `/api/chat`, `/api/otp`, `/api/simple`.

## ما لم يُبنَ بعد / حدوده
- لا webhook وارد لواتساب أو البريد في المستودع (الوارد عبر n8n)؛ قسم واتساب في `/ops` يعرض الطلبات ذات المصدر واتساب ويحوّل المحادثات يدوياً.
- الموعد يُثبَّت ويُبلَّغ عبر `api/book.js`؛ لا محرك توفر.
- الفاتورة في وضع الاختبار تُولَّد داخل الطلب؛ في الإنتاج تمر بالدفترة عبر مسار الدفع القائم.
- DocuSign غير مستخدم في هذا المسار؛ التوقيع داخل البوابة مع بصمة العقد وIP والوقت.

# نقل ويبهوكات AI Space/جارفس من n8n Cloud إلى n8n على Azure

الغرض: اللوحة الموحّدة (`ai-space/UNIFIED.md`) تقرأ كل شيء عبر وسيط Azure، وما زال بعض ما تحتاجه على n8n Cloud. هذا الجرد بالأسماء لا بالقيم السرّية. **لم يُعدَّل ولم يُفعَّل أي سير في Cloud أو Azure.**

## ١) ما يعمل أين (فحص مباشر لـn8n Azure، 2026-10-17)

الفحص أظهر أن النسخ **موجودة أصلاً على n8n Azure ومفعّلة** (تغيّرت الحال بعد مذكرة 2026-10-12)، فلا نقل مطلوب لها. المسارات سرّية: تُنسخ من عقدة الويبهوك في n8n إلى إعدادات SWA.

| الوظيفة | السير على Azure (المعرّف) | عقدة الويبهوك | الحماية | الإعداد في SWA |
|---|---|---|---|---|
| محادثة فرح | 🧠 فرح — رئيسة المكتب التنفيذي (`g2Y2k2KbxYwmhSqu`) | `Command Space Direct In` (POST) | Header Auth v3 | `BP_PATH_CHAT` (أو مسار الـAsync أدناه) |
| محضر اجتماع | 🎙️ فرح — محضر اجتماع (`zteADpS9yormFBZC`) | `Meeting In` (POST) | Header Auth — محاضر فرح (v2) — **مفتاح مختلف** | `BP_PATH_MINUTES` (لا يعمل بمفتاح فرح؛ يحتاج `BP_BASE`/مفتاحاً خاصاً — لا واجهة له الآن) |
| النبض | 🛰️ Jarvis — Pulse (`zfKGqsftT9xIoh0v`) | `Pulse GET` | بلا اعتماد (مسار سرّي) | `BP_PATH_PULSE` |
| النطق | 🔊 Jarvis — Voice (`TfasSdJrcQHPCe4O`) | `Voice POST` | بلا اعتماد (مسار سرّي) | `BP_PATH_VOICE` |
| بيانات اللوحة · النطق · التفريغ | 🛰️ BP AI Space — Data API (`7lS3TRRqHLu9SaS0`) | `Space Data` GET · `Voice` POST · `Transcribe` POST | بلا اعتماد (مسار سرّي) | `BP_PATH_DATA` · `BP_PATH_VOICE` · `BP_PATH_STT` |
| الرد الطويل (جديد) | ⏱️ فرح — Command Space غير متزامن (`tMahiYKseeoxDRQu`) | `Async In` (POST) · `Result In` (GET) | Header Auth v3 (نفس مفتاح فرح) | `BP_PATH_CHAT` · `BP_PATH_CHAT_RESULT` |

ملاحظات:
- النبض والصوت والبيانات بلا اعتماد على الويبهوك نفسه (السرّية بالمسار فقط، كما كانت على Cloud). وسيط SWA يخفي المسار عن المتصفح، لكن يُستحسن لاحقاً إضافة Header Auth لها وإرسال المفتاح من الوسيط.
- مسار «صفحة جارفس القديمة» (`Jarvis Page GET` في سير الصوت) ما زال على Azure أيضاً؛ تُستبدل باللوحة الموحّدة، وإيقافها قرارك.
- الصوت والبيانات يلزمهما اعتماد «Azure Speech — Jarvis»، وقد فُحصت اعتماداتهما سابقاً في المذكرة.

## ٢) الخطوات المتبقية

1. إدخال إعدادات `BP_*` في SWA (أنت).
2. بعد التجربة الناجحة: إيقاف نظائر Cloud وتدوير مساراتها.
3. تفعيل سير الـAsync (قرارك، §٣).

## ٣) سير الرد الطويل — مبني وغير مفعّل

`ops/azure-n8n/farah-async.mjs` (اختباره `farah-async.test.mjs`) أنشأ سيراً واحداً **غير مفعّل** بمعرّف `tMahiYKseeoxDRQu` فيه ويبهوكان يتشاركان بيانات السير الثابتة:

- **Async In (POST)**: يولّد `job_id`، يردّ `202` فوراً، ثم يستدعي ويبهوك Command Space الحقيقي (حتى ١٧٠ ث بنفس الاعتماد) ويخزّن الرد.
- **Result In (GET ?job=)**: يعيد `pending | done | error` (مهمة مجهولة = pending، وتُحذف المهام بعد ساعة).

للتفعيل: افتح السير في n8n ← فعّله ← انسخ مساري `Async In` و`Result In` إلى `BP_PATH_CHAT` و`BP_PATH_CHAT_RESULT`. الواجهة والوسيط جاهزان بلا تعديل. لم يُجرَّب تنفيذاً حقيقياً لأنه غير مفعّل؛ المُجرَّب اختبارات عقد الكود الثلاث وبنية السير.

## ٤) قرارات المالك المتبقية

1. تفعيل سير الـAsync (بعد قراءته في n8n).
2. إدخال إعدادات `BP_*` ورمز النشر.
3. إضافة Header Auth لويبهوكات النبض والصوت والبيانات؟

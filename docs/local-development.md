# التطوير المحلي — localhost أولاً

نطوّر على الجهاز، ولا نُنشئ نشرة على Vercel مع كل تعديل. النشرة تُطلب عند
محطة مستقرة فقط.

## التشغيل

```bash
npm install          # لا توجد اعتماديات فعلياً، لكن الأمر آمن
cp .env.local.example .env.local     # اختياري — الافتراضات مضبوطة أصلاً
npm run dev
```

ثم افتح:

```
الموقع العام        http://localhost:3000/ar
بوابة العميل        http://localhost:3000/ar/my
لوحة العمليات       http://localhost:3000/ops        (المفتاح: test-ops)
الصفحة القديمة      http://localhost:3000/ar/classic-home
حالة البيئة         http://localhost:3000/__dev
```

بالإنجليزية `/`، بالفرنسية `/fr`، بالصينية `/zh`.

| الأمر | ماذا يفعل |
|---|---|
| `npm run dev` | بناء كامل ثم تشغيل الخادم على 3000 |
| `npm run dev:serve` | تشغيل الخادم فقط (بلا إعادة بناء) — أسرع بكثير |
| `npm run dev:reset` | يمسح قاعدة البيانات المحلية ويشغّل الخادم من بذرة نظيفة |
| `PORT=4000 npm run dev:serve` | منفذ آخر |

ملفات `api/` تُعاد قراءتها عند كل طلب، فتعديل نقطة API يظهر بلا إعادة تشغيل.
تعديل صفحة (`site/scripts/*.mjs`) يحتاج `npm run dev` من جديد لإعادة التوليد.

## حسابات الاختبار المحلية

| الحساب | الدخول |
|---|---|
| عميل | `client@test.local` — الرمز `123456` |
| مسؤول | `admin@test.local` — الرمز `123456` |
| لوحة العمليات | المفتاح `test-ops` |

لا تُستخدم أي بيانات عميل حقيقية. البذرة في `db/seed.local.json`: منشأتان،
مستخدمان، ثلاثة طلبات في حالات مختلفة، ومهمتان.

## البيانات: لا مساس بالإنتاج

`LOCAL_DB=1` يحوّل كل نداءات `sb()` من Supabase إلى ملف JSON تحت `.localdb/`
(`api/_localdb.js`). الخادم **يرفض الإقلاع** إذا أُطفئ `LOCAL_DB` بلا
`LOCAL_ALLOW_REMOTE_DB=1`، ويحذف مفاتيح Supabase من البيئة عند التشغيل — حتى
لا يصير التطوير على بيانات عملاء حقيقية بالخطأ.

مرفقات الملفات تُحفظ في `.localdb/storage/` وتُقرأ من `/__localdb/storage/…`.
المجلد كله خارج المستودع.

## الأوضاع الآمنة

`api/_mode.js` يقرأ `APP_ENV=development` فيجعل كل تكامل آمناً افتراضياً:

| المتغير | محلياً | الإنتاج |
|---|---|---|
| `PAYMENTS_MODE` / `MOYASAR_MODE` | `test` | `live` |
| `TAMARA_MODE` | `sandbox` | `live` |
| `WHATSAPP_MODE` | `mock` | `live` |
| `EMAIL_MODE` | `preview` | `live` |
| `CONTRACT_MODE` | `test` | `live` |
| `CALENDAR_MODE` | `test` | `live` |

لا بطاقة تُخصم، ولا رسالة تصل عميلاً، ولا عقد قانوني يُرسل. كل ما كان
سيُرسَل يُسجَّل في `.localdb/outbox.json` ويُقرأ من اللوحة:

```
GET /api/simple?action=ops-outbox&key=test-ops
```

الإنتاج لا يتأثر: بلا `APP_ENV` تبقى كل الأوضاع `live` كما هي اليوم.

## دورة العمل

```
localhost  →  اختبار  →  تعديل  →  اختبار  →  محطة مستقرة  →  معاينة Vercel  →  مراجعة المالك
```

لا نشرة إنتاج، ولا تغيير على `businesspartner.sa`، إلا بموافقة صريحة.

## ما يمكن اختباره محلياً

الموقع العام، المحادثة الموحّدة، بوابة العميل، لوحة الإدارة، إنشاء الطلب،
تعديل نطاق الخدمة، عرض السعر، العقد والتوقيع، السلة والدفع، الفاتورة،
المواعيد، المهام، وأربع لغات — كلها تعمل على الخادم المحلي.

المحادثة تحتاج `ANTHROPIC_API_KEY` في `.env.local` لترد رداً حقيقياً؛ بدونه
تظهر رسالة التعذّر وبقية المسار يعمل كما هو.

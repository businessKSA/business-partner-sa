# الانتقال إلى Microsoft Azure — الحالة المتحقَّق منها وخطة التنفيذ

آخر تحقّق: **2026-09-23**. كل سطر «يعمل» هنا تحته فحص حيّ يمكن لأي جلسة إعادته.
ما لم يُفحص مكتوب أنه لم يُفحص. لا مفاتيح ولا أسرار في هذا الملف.

---

## 1) الخلاصة في ثلاثة أسطر

1. **Azure ليس بداية جديدة** — الذكاء والصوت يعملان عليه فعلاً في الإنتاج اليوم.
2. **الكود لبقية Azure مكتوب لكنه مُطفأ**، لأن متغيّرات البيئة لم تُضبط. لا ينقص
   برمجة، ينقص **موارد يُنشئها المالك في لوحة Azure** ثم تُلصق أسماؤها ومفاتيحها.
3. **أكبر عطل تنظيمي ليس تقنياً**: أحد عشر طلب دمج مفتوحاً كلها مسودّات، وأكثر من
   واحد منها يكرّر نفس عمل Azure. العمل موجود ولا يصل الإنتاج.

---

## 2) ما يعمل على Azure اليوم — متحقَّق منه

| الطبقة | الحالة | الفحص |
|---|---|---|
| المحادثة (نصّ) | ✅ يعمل | `GET /api/chat` → `providers:["azure","baher-n8n"]` |
| الصوت | ✅ يعمل | نفس الفحص → `voice:[{name:"azure",configured:true}]` |

المزوّدون الأربعة القدامى (Gemini · Groq · OpenAI · Anthropic) لم يعودوا في
السلسلة. الموقع على Azure وحده في هذه الطبقة.

**ثغرة قائمة في القرار نفسه:** الاحتياطي `baher-n8n` لا يحتاج مفتاحاً ويمرّ عبر
n8n إلى نماذج **ليست على Azure**. فسقوط Azure يخرج بالمحادثة خارجه بلا قرار من
أحد. مكتوبة هنا كما هي، لا مخفيّة.

---

## 3) ما كُتب كوده ولم يُشغَّل — هذه هي الفجوة الحقيقية

الكود جاهز ومُختبَر. المعطِّل الوحيد أن المتغيّر غير مضبوط في Vercel، فتسقط
الميزة على المسار القديم أو تتعطّل.

| الميزة | الملف | المتغيّرات الناقصة | الأثر الآن |
|---|---|---|---|
| **قراءة الـPDF** | `api/_docread.js` | `AZURE_DOCINTEL_ENDPOINT` · `AZURE_DOCINTEL_KEY` | ⚠️ **لا يُقرأ أي PDF** — وأكثر مستندات العملاء PDF |
| **خزنة الملفات** | `api/_azblob.js` | `AZURE_STORAGE_ACCOUNT` · `AZURE_STORAGE_KEY` | الملفات ما زالت على Supabase Storage |
| **البريد** | `api/_azure_notify.js` | `ACS_CONNECTION_STRING` · `ACS_SENDER_ADDRESS` | البريد ما زال على Resend |
| **مجلدات العملاء** | `api/_msgraph.js` | `AZURE_TENANT_ID` · `AZURE_CLIENT_ID` · `AZURE_CLIENT_SECRET` · `AZURE_GRAPH_DRIVE_ID` | لا مزامنة إلى SharePoint |

**عطل إضافي مُرصَد:** `AZURE_OPENAI_*` مضبوطة على **الإنتاج فقط** ولا وجود لها في
`preview`. أي أن نشرات المعاينة بلا ذكاء إطلاقاً، ومن يختبر عليها يرى عطلاً ليس
في الكود.

## 4) ما لا ينتقل إلى Azure — وسبب كل واحد

| النظام | السبب |
|---|---|
| ميسر · تمارا | بوابات دفع سعودية مرخّصة. لا مقابل لها في Azure، ونقلها قرار مالي وتعاقدي لا تقني |
| واتساب (Meta Cloud API) | المنصة مملوكة لميتا |
| نفاذ · اعتماد · قوى · مقيم · زاتكا · ناجز | منصات حكومية |
| DocuSign | مزوّد توقيع متعاقَد عليه |
| Notion | مستندات الأعمال — يبقى ما دام مطلوباً |

هذه تبقى **External Service** بشكل دائم، وليست تقصيراً في النقل.

## 5) الأصعب وما زال قائماً — قاعدة البيانات

`api/_db.js` يتحدث إلى **Supabase** عبر PostgREST (HTTP). وهي تحمل
**المستخدمين والجلسات والطلبات والمدفوعات** لكل المنصة — لا طبقة وكيل فقط.

عقبتان حقيقيتان:

1. المشروع يُبنى اليوم **بلا أي اعتماديات** (`installCommand: echo "no dependencies"`).
   Azure Database for PostgreSQL يحتاج مُشغّلاً (`pg`)، وإضافته تمسّ بناء الموقع كله.
2. كل نداء serverless يفتح اتصالاً — فيلزم تجميع اتصالات (PgBouncer أو
   Azure Connection Pooling) وإلا استُنزفت الحصة.

### خطة الانتقال بلا توقّف وبلا فقد بيانات

| # | الخطوة | معيار الانتقال للتالية |
|---|---|---|
| 1 | إنشاء المخطّط على Azure PostgreSQL من `db/schema.sql` كما هو | الجداول موجودة ومطابقة |
| 2 | `api/_azpg.js` يطبّق نفس واجهة `sb()` فوق `pg`، خلف `DB_DRIVER=azure` | الاختبارات تمر على المحرّكين |
| 3 | نسخ البيانات (Supabase ما زال يعمل ويخدم كل العملاء) | عدد الصفوف متطابق جدولاً جدولاً |
| 4 | **قراءة مزدوجة**: كل قراءة تُنفَّذ على الاثنين وتُقارَن، والنتيجة من Supabase | صفر اختلاف لمدة أسبوع |
| 5 | **كتابة مزدوجة**: الكتابة إلى الاثنين، والقراءة من Supabase | صفر فشل كتابة على Azure |
| 6 | تحويل القراءة إلى Azure، والكتابة تبقى مزدوجة | لا ارتفاع في الأخطاء ٤٨ ساعة |
| 7 | إيقاف الكتابة إلى Supabase | — |
| 8 | **Supabase يبقى قابلاً للرجوع أسبوعاً كاملاً** قبل أي إغلاق | قرار المالك صراحةً |

الرجوع في أي خطوة = تغيير متغيّر بيئة واحد (`DB_DRIVER`). لا نشرة ولا كود.

**هذه الخطة لا تُنفَّذ بلا موافقة المالك** — أي خطأ فيها يوقف تسجيل الدخول
والشراء على الموقع الحيّ.

## 6) أين يُشغَّل كل جزء — القرار

| الجزء | الأفضل له | السبب |
|---|---|---|
| الموقع (HTML ساكن) | **Current (Vercel)** | ١٤٧٩ صفحة ساكنة على شبكة توزيع عالمية وسعرها صفر تقريباً. نقلها إلى Azure تكلفة بلا مكسب |
| الـAPI (`api/`) | **Azure Container Apps** | Vercel يحدّها بـ**١٢ دالة ونحن على ١٢ بالضبط** — أي ميزة جديدة تكسر البناء. Azure يرفع السقف من أصله |
| قاعدة البيانات | **Azure Database for PostgreSQL** (لاحقاً) | ضمن المنحة، ونفس محرّك Supabase. لكن بعد الخطة أعلاه لا قبلها |
| الملفات | **Azure Blob Storage** | الكود جاهز، ينقص المتغيّران |
| البريد | **Azure Communication Services** | الكود جاهز، ينقص المتغيّران + تحقّق SPF/DKIM |
| الذكاء | **Azure OpenAI** ✅ | يعمل فعلاً |
| n8n | **Azure Container Apps** (لاحقاً) | يعمل اليوم على n8n Cloud. النقل ممكن لكنه ليس الأولوية |
| الأتمتة المستمرة | **Azure Container Apps + Service Bus** | تحتاج عملاً ٢٤/٧ لا محادثة مفتوحة |
| السكربتات والبناء | **Terminal** | تشغيل عند الطلب، لا تحتاج خادماً |
| التفكير والتخطيط | **Claude / ChatGPT** | ليست خدمة تُستضاف |

**لماذا الـAPI أولاً وليس قاعدة البيانات:** سقف الاثنتي عشرة دالة يمنع أي ميزة
جديدة اليوم. وهو انتقال بلا فقد بيانات — ننشر نسخة على Azure، نختبرها، ثم نحوّل
المسار. أما القاعدة ففيها بيانات العملاء، فتأتي بعدها.

## 7) ما لا يمكن عمله من داخل جلسة Claude

هذه ليست كسلاً — هي حدود البيئة، مكتوبة حتى لا تكتشفها كل جلسة من جديد:

- `az` غير مثبّت في الحاوية.
- `management.azure.com` محجوب بسياسة شبكة البيئة.
- لا متغيّرات Azure في بيئة الحاوية.
- قيم المفاتيح في Vercel **مُعمّاة** ولا تخرج منه.
- اعتمادات n8n **تُقرأ ولا تُنشأ** عبر الواجهة البرمجية.

**النتيجة:** إنشاء موارد Azure وضبط مفاتيحها **خطوة المالك وحده**. كل ما عداها
أستطيع تنفيذه.

## 8) قائمة المالك — أقصر طريق لتشغيل الباقي

كل بند: أنشئ المورد في لوحة Azure، ثم أضف المتغيّرات في
Vercel → Project → Settings → Environment Variables، واختر **Production و Preview معاً**.

1. **Document Intelligence** → `AZURE_DOCINTEL_ENDPOINT` · `AZURE_DOCINTEL_KEY`
   → يُعيد تشغيل قراءة الـPDF المتوقّفة. **الأعلى أثراً.**
2. **Storage Account** (حاوية **خاصة** اسمها `client-documents`)
   → `AZURE_STORAGE_ACCOUNT` · `AZURE_STORAGE_KEY`
3. **Communication Services + Email** (مع تحقّق SPF و DKIM للنطاق)
   → `ACS_CONNECTION_STRING` · `ACS_SENDER_ADDRESS`
4. **تطبيق في Entra ID** بصلاحيات Application وموافقة المسؤول
   (`Files.ReadWrite.All` · `Sites.ReadWrite.All`)
   → `AZURE_TENANT_ID` · `AZURE_CLIENT_ID` · `AZURE_CLIENT_SECRET` · `AZURE_GRAPH_DRIVE_ID`
5. **نسخ `AZURE_OPENAI_*` الثلاثة إلى بيئة `preview`** — لا تحتاج مورداً جديداً،
   نسخٌ فقط، ويُصلح غياب الذكاء عن نشرات المعاينة.
6. **اعتماد `azureOpenAiApi` في n8n** — من واجهة n8n مباشرة. انتبه: النوع المطلوب
   `Azure OpenAI` وليس `Azure DevOps` ولا `Microsoft Entra` (وقع هذا الالتباس من قبل).

## 3) ما أُصلح في هذه الدفعة

**الموزّع** (`LZ5BqoVTwlYv3LOI`)، نسخة `c140ce98`، منشورة:

```
قبل:  اقرأ أقدم 2 ← سجل الوكيل ← وجّه ← قابل للإرسال؟ ← …
بعد:  اقرأ أقدم 20 ← أبعد مهام باهر وسلاسل الإعادة ← خذ 2 ← سجل الوكيل ← …
```

- مهام بوابة الموافقة **تبقى `queued`** وتُرسل حين تُعتمد — لم يتغير معناها.
- سلسلة الإعادة الثانية فأعمق (`-RECIRC-2` وما بعدها) لا تُرسل.
- حجم الدفعة ما زال 2 — لم يتغير زمن التشغيل.
- **الرجوع:** استعادة النسخة `8be67ff0` من سجل نسخ الـworkflow.
- **التحقق:** تنفيذ `114091` (05:35 UTC) — مهمتان في الطابور (مهمة باهر وسلسلة الإعادة)
  استُبعدتا كلتاهما، لم يُرسل شيء، التشغيل ناجح.

## 4) الهيكل المستهدف

```
باهر
 ↓  هدف واحد («زد المبيعات»)
المدير التنفيذي الذكي   ← يبنى (§5 المرحلة 2)
 ├── المنسّق            ← الموزّع الحالي
 ├── المراقب            ← Watchdog + رصد المهام العالقة
 ├── مهندس الأتمتة      ← رامي، يُفعَّل
 └── مصنع الوكلاء       ← يُبنى أخيراً، بشروط
 ↓
المدراء الأحد عشر (موجودون)
 ↓
المتخصصون (يُفعَّلون واحداً واحداً حين يثبت الضغط)
```

**لا وكلاء جدد الآن.** السجل فيه 56 اسماً و11 عاملاً فقط. الخطوة الصحيحة
تشغيل الموجود لا إضافة أسماء.

### مسار المهمة

```
NEW → QUEUED → IN_PROGRESS → (REVIEW) → COMPLETED
                  ↓ فشل / مهلة
              FAILED → RETRY (حتى 3) → BLOCKED → يصعد للمدير
```

### التصعيد

متخصص → مدير الإدارة → المدير التنفيذي → باهر. لا يتجاوز أحد مديره إلا في
حادث أمني أو توقف إنتاج.

## 5) الخطة على Azure — بلا توقف وبلا فقد بيانات

كل مرحلة تُبنى بجانب القديم، وتُختبر، ثم يُحوَّل إليها. القديم لا يُطفأ إلا بعد
التأكد.

| المرحلة | العمل | يحتاج من باهر |
|---|---|---|
| **1. إصلاح الموجود** | معالجة الأعطال 2–5 أعلاه · رصد المهام العالقة وإعادتها · مطابقة معرّفات السجل | لا شيء |
| **2. المدير التنفيذي** | workflow يستلم هدف المالك من مُعين، يقسمه مهاماً في `BP_AI_Tasks` بمالك وموعد، ويرسل تقريراً يومياً قصيراً | لا شيء |
| **3. الذكاء على Azure** | نقل الـ11 مديراً من OpenAI/Claude إلى Azure OpenAI | **اعتماد Azure OpenAI في n8n** (المفتاح بيده) |
| **4. الطابور والبيانات على Azure** | `BP_AI_Tasks` والسجل إلى Azure PostgreSQL؛ Azure Service Bus بدل القراءة كل 5 دقائق | **وصول لاشتراك Azure** (مورد وصلاحيات) |
| **5. تشغيل n8n على Azure** | n8n على Azure Container Apps بدل n8n Cloud — نسخة موازية، ثم تحويل | موافقة (تغيير بنية إنتاج) |
| **6. المراقبة** | Application Insights + تنبيه واحد يومي بدل رسائل كل خطأ | لا شيء |

**لماذا لا أنقل n8n إلى Azure الآن:** 101 workflow تعمل على n8n Cloud، ومنها
واتساب الإنتاج. نقلها دفعة واحدة يوقف خدمات عملاء قائمة. الترتيب أعلاه يبدأ
بما لا يمسّ العميل.

**التكلفة:** لا أضع أرقاماً قبل تسعير فعلي من حاسبة Azure على الموارد المختارة.

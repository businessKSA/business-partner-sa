# معيار حزمة EOR — كل عميل بالمنهجية والتصميم والعقد نفسها

مرجعه الحي: `cases/2026-10-21-abdulmohsen-battery-eor/handoff/src/`. أي عرض لخدمة EOR/نقل الخدمات يخرج منه، ولا يُعاد تصميمه.

## الحزمة (لكل عميل)
1. **عرض السعر** — 7 شرائح رئيسية (غلاف · ماذا تحصل · من يتحمل · طريقة الدفع · أسعار النموذج 2 · رسوم التوطين · ما نحتاجه · الخطوات) + ملحق (النموذج 1 · الرسوم الحكومية · تكلفة السعودي · حسبة الأجنبي) + القبول. جملة واحدة لكل فكرة. المصدر: `gen_prop.py` + `lean_patch.py`.
2. **اتفاقية الخدمات — عقدان منفصلان:** M1 «التكلفة بشفافية» وM2 «تكلفة الموظف الكاملة». المصدر الواحد `pairs_eor.json`، ويولّدهما `make_variants.py`.
3. **اتفاقية عدم الإفصاح (NDA).**
4. **الحاسبة** (ملف HTML من `services/live-calculator`) + جدول أدلة التوطين.
كل وثيقة بثلاث نسخ: عربي · إنجليزي · ثنائي للتوقيع. العميل يوقّع الثنائي فقط.

## القواعد الثابتة (قرارات المالك)
- «التكلفة بشفافية» و«تكلفة الموظف الكاملة»؛ «رسوم التوطين» (جمع)؛ لا خيار 6 أشهر (12/24/36 فقط).
- الاستقدام من الخارج ومتطلبات السفارة وتذكرة القدوم **على العميل**.
- توطين: أخذ سعوديين معنا مقابل الأجانب = بلا رسوم؛ وإلا 900 للمهنة العادية، وتكلفة السعودي مقسومة لمهنة عليها قرار.
- راتب السعودي يُفوتَر بالتأخير بعد أول شهر؛ رسم نقل الكفالة رسم حكومي.
- ما نحتاجه من العميل: العدد، الجنسيات، الرواتب، المهن، السير الذاتية، أرقام تواصل المختارين، مختار أم استقطاب، داخل السعودية أم خارجها.
- لا أسعار خارج الكتالوج ومعادلات المالك؛ لا إرسال للعميل إلا بقرار المالك.

## عميل جديد
```bash
bash docs/sales/eor-standard/new-client.sh <slug-العميل>   # ينسخ src إلى cases/<التاريخ>-<slug>/handoff/src
```
ثم: عدّل اسم العميل والصفوف في `gen_prop.py` (`CLIENT_EN/AR`) و`pairs_eor.json` (`[[...]]` والجدول 1) والأرقام في `lean_patch.py`، وشغّل `bash run_all.sh`. النتائج في `src/pdfout/`.

## ما يتغير وما لا يتغير
يتغير: اسم العميل، الصفوف والمهن والرواتب، العدد، الأسعار من الحاسبة. لا يتغير: البنية والتصميم وبنود العقد وقواعد التوطين.

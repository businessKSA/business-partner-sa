# بروتوكول الاستلام — كيف تصل الطلبات إلى بدر

**المشكلة (المالك، 2026-10-17):** الطلبات تصل بالاتصال أو واتساب أو الإيميل أو الموقع أو السوشال، ومن ثلاثة أنواع مصادر
(شخص · شركة · مستشار ذكي)، وتمرّ على فرح، بينما جلسة بدر لا تعلم عنها شيئاً.

## الحل: صندوق واحد — جدول `BP_AI_Tasks` في n8n

ما لا يصل إلى الجدول لا يراه بدر. فرح (`chief_of_staff`) تكتب كل طلب يخص المبيعات في الجدول بالحقول التالية:

| الحقل | القيمة |
|---|---|
| `assigned_to_agent` | `badr_sales` |
| `created_by_agent` | `farah_chief_of_staff` أو الوكيل/المصدر |
| `channel` | `whatsapp` · `call` · `email` · `website` · `social` · `internal` |
| `source` | `personal` · `company` · `smart_agent` · … (نوع المصدر) |
| `client_name` | الاسم التجاري |
| `objective` / `context` | ما طُلب بكلام العميل، وروابط التسجيلات أو الرسائل |
| `status` | `queued` عند الوصول |
| `human_action_required` | `true` إن احتاج المالك |

## ما يفعله بدر

١. **أول كل جلسة:** يقرأ الصفوف `assigned_to_agent = badr_sales` التي حالتها ليست `completed`، ويصنّفها (جديد · متابعة · عاجل).
٢. لكل عميل جديد يفتح ملف حالة بوكيل `sales-client-case`؛ وللمتابعة يضيف إلى ملف الحالة القائم.
٣. يردّ في الجدول نفسه: صف جديد مربوط بـ`parent_task_id` يكتب فيه ما تمّ، أو يغيّر الحالة حيث تسمح الأداة. (الأداة الحالية تضيف صفوفاً ولا تعدّل.)
٤. يلخّص للمالك ما وصل وما بقي، ويطلب قراراً واحداً عند الحاجة.

## حدود حالية

- جلسة بدر لا تُنبَّه تلقائياً بوصول صف: القراءة عند بدء الجلسة أو بطلب المالك. تنبيه تلقائي يحتاج أتمتة n8n (رسالة لبدر عند صف جديد) وهي خارج نطاق `docs/sales/**` → تُطلب من `automation-agents`/`bp-ai-platform`.
- واتساب والبريد والسوشال لا يقرؤها بدر مباشرة؛ تصل عبر فرح أو الأتمتة إلى الجدول.

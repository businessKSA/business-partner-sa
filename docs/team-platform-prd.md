# وثيقة منتج: منصة «فريقك» — الفريق الذكي بالربط الحكومي

> Product Requirements Document — النسخة 1.0 (مسودة للنقاش الداخلي)
> المنتج: مساحة عمل يديرها فريق وكلاء ذكاء اصطناعي لشركات القطاع الخاص في السعودية، ميزتها الفارقة الربط مع المنصات الحكومية.
> النموذج الأولي للواجهة: `site/ar/team.html` (تبويبات: المحادثة / الفريق / الربط الحكومي / سجل الأعمال).

---

## 1. الرؤية في سطر

**صاحب الشركة يكتب «جدد إقامات موظفيني» فتُنفَّذ** — منصة تخفض حاجز التعامل مع الحكومة السعودية إلى أمر واحد، كما خفضت Replit حاجز بناء البرمجيات.

## 2. المشكلة

صاحب المنشأة الصغيرة والمتوسطة في السعودية يتعامل مع 8+ منصات حكومية (قوى، مقيم، التأمينات، مدد، أبشر أعمال، بلدي، وزارة التجارة، اعتماد) بواجهات وكلمات مرور ومهل مختلفة. النتيجة: غرامات بسبب مواعيد فائتة، ساعات ضائعة أسبوعيًا، واعتماد كامل على مكاتب خدمات تقليدية بلا شفافية ولا تتبع.

## 3. لماذا نحن؟ (الخندق التنافسي)

| الأصل | حالته اليوم |
| --- | --- |
| فريق تشغيلي مرخص يدير المنصات الحكومية فعليًا لعملاء حقيقيين | ✅ يعمل (92 خدمة) |
| 12 وكيل ذكاء اصطناعي على n8n (خالد المنسق + 11 متخصصًا) | ✅ يعمل (`docs/shared-services-team-architecture.md`) |
| موقع حي مع بوابة عملاء وصفحة صوتية وproxy للوكلاء (`api/agent.ts`) | ✅ يعمل |
| لوحة امتثال (compliance dashboard) | ✅ تعمل |
| قاعدة عملاء مشتركين في باقات شهرية | ✅ قائمة |

أي مطوّر يستطيع بناء واجهة؛ لا أحد غيرنا يملك الفريق المرخص + العلاقات + العمليات القائمة. **الميزة «المرعبة» ليست تقنية — تشغيلية.**

## 4. مبدأ المنتج الحاكم: Service-as-Software

كل خدمة تُعرض للعميل كأنها زر آلي. خلف الكواليس ثلاث طبقات بترتيب الأولوية:
1. **API رسمي** حيثما توفر (واثق، نفاذ، تكامل قوى لاحقًا).
2. **الفريق التشغيلي** حيثما لا يتوفر API — بوقت استجابة معلن (SLA) وتتبع حالة.
3. **الذكاء الاصطناعي** يجهز ويدقق ويتنبأ في كل الحالات — والإنسان يعتمد القرارات الملزمة (مال/توقيع/حكومة).

**قاعدة صدق ثابتة:** واجهة الربط الحكومي تميز بوضوح: 🟢 ربط رسمي / 🟡 عبر الفريق—SLA / ⚪ قريبًا. لا ندّعي أتمتة غير موجودة — الشفافية ميزة بيع.

**خط أحمر:** لا أتمتة متصفح على البوابات الحكومية إطلاقًا (مخالفة شروط + خطر على التراخيص).

## 5. قنوات الربط الحكومي

| القناة | ما تتيحه | الحالة المستهدفة |
| --- | --- | --- |
| واثق (وزارة التجارة) | بيانات السجل التجاري لحظيًا | 🟢 مرحلة 1 — تسجيل مباشر، API مدفوع |
| نفاذ | تحقق هوية ودخول رسمي | 🟢 مرحلة 1 — عبر مزود معتمد |
| تكامل قوى | عقود، رخص عمل، نطاقات | 🟡→🟢 تقديم رسمي بصفتنا مزود خدمات HR |
| مدد | رواتب وحماية أجور | 🟡 عبر الفريق، تقييم API لاحقًا |
| مقيم / أبشر أعمال | إقامات، تأشيرات، تفاويض | 🟡 عبر الفريق (تفويض ساري) |
| التأمينات الاجتماعية | تسجيل، أجور، سعودة | 🟡 عبر الفريق |
| بلدي / اعتماد | رخص بلدية، منافسات | ⚪ قريبًا |
| البيانات المفتوحة (data.gov.sa) | تغذية تنبؤات الوكلاء | 🟢 فوري، مجاني |

## 6. تجربة المستخدم — ثلاث شاشات فقط

1. **المحادثة (خالد):** نقطة الدخول الوحيدة. طلب بالعربي → خالد يوجه للمتخصص → رد بالنتيجة أو بطلب اعتماد. مثال معياري: «كم موظف تنتهي إقامته خلال 60 يومًا؟» → قائمة + تكلفة + «هل أجهز التجديد؟».
2. **الربط الحكومي:** كروت الجهات بالحالات الثلاث + آخر مزامنة/عملية. هذه شاشة البيع.
3. **سجل الأعمال:** كل ما نُفذ وما ينتظر الاعتماد، مع التنبيهات الاستباقية (انتهاء رخص/إقامات قبل الغرامة).

(شبكة الفريق تبويب رابع داعم — تُظهر «الموظفين» الـ12 وتخصصاتهم.)

## 7. مراحل التنفيذ

### المرحلة 0 — التوحيد (شهر)
- ترقية النموذج `site/ar/team.html` لواجهة حية: ربط المحادثة بـ`api/agent.ts` القائم، وسجل الأعمال بقاعدة نوشن.
- حساب عميل واحد تجريبي (عميل حقيقي متعاون) يستخدمها بدل الواتساب.
- **مقياس النجاح:** العميل التجريبي ينفذ 10 طلبات كاملة من المنصة دون قناة أخرى.

### المرحلة 1 — أول ربط رسمي (شهران–ثلاثة)
- تفعيل واثق (بيانات السجل التجاري داخل المنصة).
- دمج نفاذ للدخول عبر مزود معتمد.
- تقديم طلب رسمي لبرنامج تكامل قوى.
- إطلاق تجاري محدود: 10–20 عميلًا من المشتركين الحاليين.
- **مقياس النجاح:** كرتان أخضران حقيقيان + 10 عملاء يدفعون للمنصة (وليس للخدمات فقط).

### المرحلة 2 — طبقة الذكاء الاستباقي (شهران)
- وكيل مراقبة (Claude API): يقرأ مواعيد الانتهاء ويولد تنبيهات قبل 60/30/7 أيام مع التكلفة والإجراء.
- تجهيز تلقائي للطلبات: المستندات، النواقص، الرسوم — والموظف يعتمد بضغطة.
- **مقياس النجاح:** 80% من التجديدات تبدأ بتنبيه استباقي لا بطلب عميل.

### المرحلة 3 — متجر الأتمتات (بعد إثبات 1 و2)
- قوالب سيناريوهات جاهزة يفعّلها العميل: «موظف جديد → عقد قوى + تأمينات + مدد»، «نهاية شهر → مسير رواتب»، «قبل انتهاء أي رخصة → تجديد تلقائي بعد اعتماد».
- n8n تحت الغطاء، واجهة تفعيل بسيطة فوقه. هذا هو «شبه Replit» — ولا يُبنى قبل إثبات المرحلتين السابقتين.

## 8. نموذج الإيراد

- **اشتراك المنصة** فوق الباقات الحالية: شريحة أساس (الرصد والتنبيهات وسجل الأعمال) وشريحة تنفيذ (عمليات شهرية مشمولة حسب حجم المنشأة).
- رسوم لكل عملية فوق الحد المشمول (تتماشى مع تسعير الخدمات الـ92 القائم).
- الجهات 🟡 تُسعّر بهامش خدمة؛ الجهات 🟢 بهامش برمجي أعلى — **كل ربط رسمي جديد يرفع الهامش تلقائيًا.**

## 9. الالتزام والمخاطر

| الخطر | التخفيف |
| --- | --- |
| بيانات موظفي العملاء (PDPL) | سياسة خصوصية وموافقات صريحة من اليوم الأول؛ تخزين داخل السعودية حيث يلزم؛ تعيين مسؤول حماية بيانات |
| رفض/تأخر برنامج تكامل قوى | المنتج يعمل كاملًا بالطبقة 🟡؛ الربط الرسمي يحسّن الهامش ولا يوقف الإطلاق |
| اعتماد العملاء على قناة واحدة (المنصة) | SLA داخلي + مسار تصعيد بشري دائم |
| تغير أنظمة المنصات الحكومية | مراجعة ربع سنوية؛ فريق العمليات هو صمام الأمان |

## 10. قرارات مفتوحة (تحتاج قرار المالك)

1. اعتماد اسم «فريقك» للواجهة نهائيًا (التوصية: نعم، و«Shared Services Team» يبقى اسم الباقة B2B).
2. اختيار العميل التجريبي للمرحلة 0.
3. ميزانية اشتراك واثق وقناة نفاذ (مزود الاعتماد).
4. تسعير شريحتي الاشتراك.

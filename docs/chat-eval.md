# قياس المستشار الذكي — مجموعة القياس الدائمة

> وُلدت من أمر المالك (2026-10-21): «اختبر المحادثات وشوف الخلل وعدّله للمرات الجايه وخلي النموذج يتعلم بشكل قوي».
> المستشار لا يتعلم من محادثاته (لا نحفظها — قرار الحفظ ينتظر موافقة المالك والخصوصية). «يتعلم» هنا يعني شيئاً
> محدداً: **كل خطأ يُكتشف يصير حالة دائمة تُقاس بعد كل تعديل، وحارساً على الخادم يمنعه ولو أخطأ النموذج.**

## الطبقات الثلاث

| الطبقة | أين | متى تعمل | تحتاج نموذجاً؟ |
|---|---|---|---|
| **حراس الخادم** | `api/_chat-guards.js` (+ `guardReply` في `api/chat.js`) | مع كل ردّ يخرج لعميل | لا — حتميّة |
| **اختبارات الوحدة** | `tests/chat-guards.test.mjs` · `tests/chat-eval-checks.test.mjs` | ضمن `npm test` | لا — ردود مُحاكاة مأخوذة من الفشل الحقيقي |
| **مجموعة القياس** | `tests/chat-eval/` | `npm run chat:eval` | **نعم** — ليست ضمن `npm test` |

الأولى تضمن أن الخطأ المعروف لا يصل عميلاً. الثانية تضمن أن الحارس لا يظلم ردّاً سليماً. الثالثة تقيس **النموذج
نفسه** (تعليماته ومعرفته) على أسئلة حقيقية، فتكشف ما لم نتوقعه بعد.

## التشغيل

```bash
# على خادم يعمل فيه النموذج (التجريبي مثلاً). يقرأ /api/chat وحده ولا يكتب في أي قاعدة.
CHAT_EVAL_BASE=https://azure.businesspartner.sa npm run chat:eval

# محلياً: يلزم مفتاح Azure OpenAI في .env.local (بدونه يردّ الخادم «المحادثة الذكية معطّلة محلياً»)
npm run dev                      # في نافذة
npm run chat:eval                # CHAT_EVAL_BASE الافتراضي http://localhost:3000
```

| متغير | الأثر |
|---|---|
| `CHAT_EVAL_BASE` | عنوان الخادم (الافتراضي `http://localhost:3000`) |
| `CHAT_EVAL_ONLY=C26,X06` | حالات بعينها (`node tests/chat-eval/run.mjs --list` يسردها) |
| `CHAT_EVAL_CONCURRENCY` | محادثات متوازية (الافتراضي 3 — لا ترفعه فوق ما يحتمله الحدّ في Azure) |
| `CHAT_EVAL_TIMEOUT_MS` | مهلة النداء الواحد (75000) |
| `CHAT_EVAL_OUT` | مسار تقرير JSON (الافتراضي `.chat-eval/report-<وقت>.json`، خارج git) |
| `CHAT_EVAL_REPLAY=<تقرير>` | يعيد **تقييم** تقرير محفوظ بالفحوص الحالية دون نداء النموذج — يوم تضيف فحصاً جديداً |

رمز الخروج: `0` كلها نجحت · `1` فشلت حالة أو أكثر · `2` تعذّر الوصول إلى النموذج في حالة أو أكثر.

**لا تشغّلها على الإنتاج الحيّ** بلا حاجة: كل تشغيل نحو 100 نداء للنموذج (يُدفع من رصيد Azure). والتجريبي هو المكان المقصود.

## متى نشغّلها

- بعد **أي** تعديل على: `api/knowledge.json` · `api/_knowledge.js` · `intakeInstructions` / `SYSTEM_INSTRUCTIONS` في `api/chat.js` ·
  `api/_chat-guards.js` · الكتالوج (`site/assets/data/catalog.json`: أكواد الخدمات وأسماؤها تدخل في فحص الأكواد).
- بعد تغيير نشر النموذج (deployment) أو نسخته في Azure، أو منطقة التكرار.
- قبل أن يدمج المدير فرعاً يمسّ ما سبق، وبعد أي دمج من هذا النوع على التجريبي.

والتقرير يُقرأ هكذا: الحالات الفاشلة أولاً مع سبب كل إخفاق ورقم الرسالة، ثم نسبة النجاح لكل **فحص** (لا لكل حالة) —
انخفاض فحص واحد عبر حالات كثيرة يعني خللاً في التعليمات، وفشل حالة واحدة يعني خللاً في موضوعها.

## حلقة التعلّم: كل خطأ جديد يصير حالة دائمة

1. **التقط الخطأ حرفياً.** انسخ الرسالة التي كتبها العميل (بلا اسم ولا رقم جوال ولا بريد ولا رابط — اختبار
   `chat-eval-checks` يرفض ذلك) والردّ الفاشل كما خرج.
2. **أضف الحالة إلى `tests/chat-eval/golden.json`:**
   ```json
   {
     "id": "C29",
     "title": "وصف قصير بالعربية للخطأ",
     "category": "ما يصنّفه",
     "mode": "intake",
     "context": "government",
     "lang": "ar",
     "turns": ["رسالة العميل الأولى", "@opt0|نص احتياطي إن لم تظهر الخيارات", "رسالة ثالثة"],
     "expect": { "scopeBy": 3, "mustNotMatch": [{ "re": "العبارة التي لا يجوز أن تظهر", "flags": "u" }] }
   }
   ```
   `mode: "public"` للمحادثة العامة (بلا `context`). الفحوص الافتراضية (`defaults` في أول الملف) تُطبَّق تلقائياً؛
   اكتب في `expect` ما يخصّ الحالة فقط، و`null` يُسقط فحصاً افتراضياً عنها.
3. **شغّلها وتأكد أنها تفشل** على النسخة التي أخطأت: `CHAT_EVAL_ONLY=C29 npm run chat:eval`.
4. **أصلح بالترتيب:** (أ) حارس خادم في `api/_chat-guards.js` إن أمكن ضبطه حتمياً — دالة صغيرة نقيّة؛
   (ب) سطر في `intakeInstructions`/`SYSTEM_INSTRUCTIONS` إن كان سلوكاً لا يُضبط بحارس؛ (ج) المعرفة إن كانت معلومة ناقصة.
5. **اكتب اختبار وحدة** في `tests/chat-guards.test.mjs`: الرد الفاشل **حرفياً** ← ما يخرج بعد الحارس، **وحالة سلبية**
   تثبت أن الحارس لا يمسّ ردّاً سليماً مشابهاً (هذا ما يمنع الحارس من أن يصير هو الخلل).
6. أعد `npm run chat:eval` ثم `npm test`. إن أضفتَ فحصاً جديداً فأضف اسمه إلى `CHECKS` في `checks.mjs` وإلى الجدول أعلاه.

لا تضعف حالةً قديمة لأنها «تفشل أحياناً»: فشلها المتقطع هو المعلومة. وإن غيّر المالك سياسة (مثلاً أُظهر باب)، فعدّل
توقعاتها في الدفعة نفسها واذكر القرار في رسالة الكوميت.

## ما تفعله الحراس (مرجع سريع)

| الخلل | الحارس | أين |
|---|---|---|
| وعد تصعيد / «رقمك المسجل» / لا رقم لمن طلب إنساناً | `ensureHumanContact` (كاشف كلمات بأربع لغات + استبدال بردّ ثابت فيه الرقم والرابط) | `_chat-guards.js` |
| النطاق لا يخرج | `shouldForceScope` ← إعادة نداء واحدة بـ`FORCE_SCOPE_NOTE` ← `intakeFallback` | `_chat-guards.js` + معالج `chat.js` |
| سؤالان في رد | `oneQuestion` (يبقى الأخير لأن `<<OPTS>>` تجيب عنه) | `_chat-guards.js` |
| مدة مخترعة | `guardDurations` (تُحايَد بـ«مدة تحددها الجهة المختصة»؛ الجملة تبقى) | `_chat-guards.js` |
| عنوان يتيم وجملة حجب وسط الشرح | `redactSegments` | `chat.js` |
| `type` مزدوج، كود في غير معناه | `sanitizeScope` (`normalizeScopeType` · `codeFits`) | `_chat-guards.js` |
| بيانات دخول كمستند | `sanitizeScope` + `guardCredentials` ← بند «تفويض أو وكالة» | `_chat-guards.js` |
| الباب الرابع المخفي يُجاب بصيغ مختلفة | `bizdevUnavailable` (صيغة موحّدة) | `_chat-guards.js` |

تعريف «ورد حرفياً» للمدد: مدة (رقم أو نطاق + وحدة، بعد توحيد الأرقام الهندية وفواصل `–`/`-`/`إلى`/`to`/`à`) ظهرت في
**المقاطع المرفقة بالنموذج في ذلك الدور** (`pickKnowledge` على آخر رسالتين) أو في كلام العميل نفسه. يُقبل رقم مفرد يساوي
طرفاً من نطاق وارد بالوحدة نفسها («10 أيام» من «3–10 أيام»)، ولا يُقبل نطاق غير وارد. السنة التقويمية (2015) وأعداد
الموظفين وأرقام المستندات والهاتف ليست مدداً.

## حدود معروفة

- الحارس لا يحكم على **صحة** معلومة وردت في القاعدة، يحكم على أن الرقم ليس مخترعاً.
- `codeFits` لغوي (كلمة جوهرية مشتركة + فعل التعديل/التجديد/الإلغاء + تعارض الجهة). بنودٌ بالفرنسية/الصينية لا تُطابَق
  بالعربية فيسقط كودها ويبقى البند، إلا الخدمة التي اختارها العميل من الموقع فتبقى بكودها دائماً.
- حارس الأسعار وحارس المدد يعملان على النثر وكتلة النطاق؛ المحادثة العامة لا تمرّ بحارس المدد (التعليمات وحدها).
- القياس بنموذج حيّ غير حتمي: حالة تفشل مرة ثم تنجح تُقرأ على أنها غير مستقرة، ويُرفع عددها لا يُتجاهل.

## قرارات تنتظر المالك

- **الرسوم الحكومية الرسمية (منفصلة عن أتعاب BP):** السياسة تسمح بذكرها، لكن الحارس يقرأ كل سطر منفرداً فيحجب
  بنود قائمة تحت عنوان «الرسوم الحكومية». اقتراح (غير مطبّق): عدّ بنود القائمة التي تحت عنوان فيه «حكومية» رسوماً حكومية ما لم
  يرد فيها «أتعاب/باقة/خدمتنا». لم يُطبَّق لأن SHOW_PRICES=false وقراره للمالك.
- **حفظ المحادثات للتعلّم:** لم يُبنَ شيء. القياس هنا على أسئلة اصطناعية مجهّلة؛ حفظ محادثات العملاء الحقيقية يحتاج موافقة وسياسة خصوصية.

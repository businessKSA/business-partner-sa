# نظام عروض الأسعار والعقود — شركة بزنس بارتنر سلوشنز

نظام ويب لإدارة عروض الأسعار والعقود من الإنشاء حتى التوقيع والدفع والتنفيذ.
واجهة عربية RTL أساسية، وكل المستندات ثنائية اللغة بعمودين متقابلين
(الإنجليزي يسار والعربي يمين).

---

## التشغيل

يحتاج النظام قاعدة **PostgreSQL**. للتطوير المحلي أنشئ قاعدة فارغة أو استخدم
قاعدة مجانية من Neon، ثم:

```bash
cd quotes
cp .env.example .env       # ضع DATABASE_URL و DIRECT_DATABASE_URL
npm install
npm run setup              # توليد Prisma + إنشاء الجداول + بيانات الكتالوج
npm run dev                # http://localhost:3000
```

الدخول: افتح `/admin/login` وأدخل البريد المضبوط في `ADMIN_EMAIL`.
مع `DEV_SHOW_MAGIC_LINK=1` يظهر رابط الدخول على الشاشة مباشرة بدل إرساله بالبريد.

### اختبار السيناريو الكامل

```bash
npm run build && npm start &     # لا بد من خادم يعمل لتوليد الـPDF
npm run smoke
```

يشغّل 84 فحصاً يغطي: إنشاء العميل ومجلده ← عرض بخدمتين والحسابات ←
حارس الاعتماد ← الإرسال ← القبول الأونلاين ← توليد العقد ← دورة DocuSign
كاملة ← الدفع ← فلو الموردين ← الخط الزمني ← سلامة سجل التدقيق.

## القواعد المفروضة في الكود

1. **ثنائية اللغة إلزامية** — كل مستند بعمودين متقابلين، RTL كامل للعربي.
2. **ممنوع الإيموجي والأيقونات** في أي مخرج يصل العميل. يُفرض في
   `src/lib/content-guard.ts` ويُفحص قبل كل إرسال وعلى كل مخرجات الوكيل الذكي.
3. **أسماء الجهات الحكومية كاملة** — الاختصارات تُوسَّع تلقائياً. أسماء
   المنصات (قوى، مدد، مقيم، ناجز) تبقى كما هي.
4. **الأسعار غير شاملة ضريبة القيمة المضافة 15%** — الضريبة سطر مستقل ثم
   الإجمالي شامل الضريبة.
5. **الرسوم الحكومية مستثناة دائماً** وتُسدَّد للجهات مباشرة بالتكلفة الفعلية —
   العبارة مطبوعة في كل عرض وعقد.
6. **لا إرسال قبل الاعتماد البشري** — `assertSendable()` تحرس كل قناة إرسال
   بلا استثناء، والصفحة العامة ترد 404 على المسودات.

## البنية القابلة للتوسّع

ثلاث طبقات تجريد تجعل النظام يقبل خوادم متعددة:

| الطبقة | التطوير | الإنتاج | المتغيّر |
|---|---|---|---|
| قاعدة البيانات | PostgreSQL محلية | Neon أو أي Postgres مُدارة | `DATABASE_URL` |
| التخزين | قرص محلي | S3 أو R2 مع روابط موقّعة مؤقتة | `STORAGE_DRIVER` |
| الطابور | تنفيذ داخل الطلب | Inngest على Vercel | `QUEUE_DRIVER` |
| توليد المستندات | Chromium محلي | `@sparticuz/chromium` داخل دالة | `PDF_DRIVER` |

**لماذا الطابور:** توليد المستند يستغرق ثوانيَ، ولو نُفِّذ داخل الطلب لحجز
العملية وحدّ من عدد الطلبات المتزامنة. الآن الطلب يكتفي بإضافة مهمة ويرجع
فوراً، وعمّال مستقلون ينفّذون. كل مهمة مسجّلة في جدول `Job` بحالتها ومحاولاتها،
وتظهر في صفحة المستند مع زر إعادة تشغيل للفاشلة.

**مفتاح التفرّد** يمنع تكرار نفس المهمة عند الضغط مرتين أو إعادة الإرسال.

## هوية العميل الموحّدة

نفس الشخص يصل من الواتساب برقمه، ومن البريد بعنوانه، ومن الموقع بجلسته.
`ClientIdentity` تربط كل هذه بملف عميل واحد، و`resolveClient(channel, value)`
تجده من أي قناة بأي صيغة (`0501234567` و`+966501234567` نفس الهوية).
تُنشأ الهويات تلقائياً مع كل عميل جديد.

## توليد المستندات

**PDF** يُنتَج بطباعة **نفس صفحة المستند** من Chromium
(Playwright print-to-PDF)، فيخرج مطابقاً للصفحة حرفياً.

**DOCX** يُبنى من نفس نموذج العرض عبر مكتبة `docx`، فتبقى الصيغ الثلاث متطابقة
المحتوى. العربية في DOCX تحتاج ثلاثة أشياء معاً وإلا خرجت مقلوبة:
`bidirectional` على الفقرة، و`rightToLeft` على النص، و`visuallyRightToLeft`
على الجدول — الثلاثة مطبّقة، ويتحقق اختبار القبول من وجودها ومن سلامة علامات
ربط DocuSign داخل الملف.

**لماذا لا `@react-pdf/renderer`:** محرك Chromium يتولى تشكيل الحروف العربية
(Arabic shaping) وربطها والاتجاه ثنائي الاتجاه (bidi) بشكل صحيح تماماً، وهو ما
لا تضمنه المكتبات التي ترسم النص حرفاً حرفاً. خط **Tajawal** مستضاف محلياً في
`public/fonts/` فلا يعتمد التوليد على الشبكة، ويُنتظر `document.fonts.ready`
قبل الطباعة حتى لا يُطبع نص بخط بديل.

المتصفح: يُقرأ من `CHROMIUM_PATH` أو `PLAYWRIGHT_BROWSERS_PATH`، وإلا
يستخدم متصفح Playwright الافتراضي.

ومنح الموافقة لمرة واحدة وإعداد الـWebhook.

`DOCUSIGN_MODE=mock` (الافتراضي) يشغّل محاكاة محلية كاملة لدورة التوقيع بلا
حساب DocuSign — مفيدة للاختبار. اضبطه على `demo` بعد إعداد المفاتيح.

## الوكيل الذكي

للخدمات غير الموجودة في الكتالوج: أدخل الاسم والوصف والسعر وطريقة الدفع
ومدة التنفيذ، ويولّد الوكيل عرض السعر والعقد كاملين عبر Anthropic API.

- المفتاح: `ANTHROPIC_API_KEY` — النموذج: `AGENT_MODEL` (افتراضي `claude-sonnet-4-6`).
- القوالب المعتمدة موضوعة كأمثلة few-shot في `templates/agent-prompt.md`.
- **كل ما يولّده يُحفَظ مسودة إلزامياً** ولا يُرسَل قبل الاعتماد.
- البنود القانونية العامة لا يكتبها الوكيل — تأتي من قالب العقد المعتمد.
- بعد الاعتماد تُضاف الخدمة تلقائياً للكتالوج لإعادة الاستخدام.
- بدون المفتاح تظهر رسالة واضحة ويبقى بقية النظام يعمل.

## الدفع الإلكتروني

طبقة تجريد في `src/lib/payments/`. المزوّد يُبدَّل من `PAYMENT_PROVIDER`:

- `moyasar` — بوابة سعودية تدعم مدى وفيزا وآبل باي (مفاتيح Moyasar مطلوبة).
- `mock` — محاكاة محلية للاختبار بلا مفاتيح.

عند نجاح الدفع: تتحدث الفاتورة، تُقيَّد الحركة في المحفظة، وإذا كان العقد
موقّعاً والدفعة هي الأولى تتحول حالة العقد تلقائياً إلى **قيد التنفيذ**،
ويصل إشعار بالبريد.

## المحفظة وسجل التدقيق

المحفظة **دفتر حركات append-only** — الرصيد مشتق دائماً ولا يُخزَّن كحقل.
كل حركة مالية تُقيَّد في `AuditLog` المسلسل بسلسلة تجزئة (hash chain): كل قيد
يحمل تجزئة القيد السابق، فأي تعديل لاحق على أي سطر يكسر السلسلة ويُكتشف عبر
`verifyAuditChain()` وتظهر النتيجة في `/admin/audit`.

الصرف من المحفظة لا يتجاوز الرصيد المتاح، ولا يتم للموردين إلا بعد اعتماد
مرحلة الإنجاز.

## التخزين والأرشفة

طبقة تجريد في `src/lib/storage.ts`. `STORAGE_DRIVER=local` الآن،
و`s3` لاحقاً بتنفيذ دوال `s3Driver()` فقط — لا يتغير أي كود مستدعٍ.

عند إنشاء أي عميل يُنشأ مجلده تلقائياً:

```
storage/clients/<اسم-العميل>-<معرّف>/
├── quotes/        عروض الأسعار
├── contracts/     العقود + النسخ الموقّعة + شهادات الإتمام
└── attachments/   مرفقات العميل
```

كل PDF يتولّد يُؤرشف في مجلده الصحيح تلقائياً.

## النشر على Vercel

1. اربط المستودع بـ Vercel واضبط **Root Directory** على `quotes`.
2. **قاعدة البيانات:** أنشئ قاعدة على Neon واضبط:
   - `DATABASE_URL` على رابط التجميع (pooled)
   - `DIRECT_DATABASE_URL` على الرابط المباشر — تستخدمه أوامر الترحيل فقط
   ثم `npx prisma db push`.
3. **التخزين:** `STORAGE_DRIVER=s3` مع بيانات الوصول. القرص على Vercel مؤقت
   ولا يُشارَك بين النسخ، فلا بديل عنه.
4. **الطابور:** `QUEUE_DRIVER=inngest` مع `INNGEST_EVENT_KEY` و
   `INNGEST_SIGNING_KEY`. نقطة الاستقبال `/api/inngest` تُسجَّل تلقائياً.
5. **توليد المستندات:** `PDF_DRIVER=serverless` ليستخدم `@sparticuz/chromium`.
   واضبط `INTERNAL_URL` على نطاق الإنتاج ليفتح المتصفح صفحة الطباعة.
6. اضبط `APP_URL` على نطاق الإنتاج (يُستخدم في الروابط العامة وwebhooks).
7. حدّث Redirect URI في DocuSign وعنوان الـWebhook على النطاق الجديد.

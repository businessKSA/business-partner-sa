# نظام تخطيط موارد المؤسسات — بزنس بارتنر

نظام محاسبي وإداري متكامل، **عربيٌّ أصلاً لا مترجَماً**، متعدّد المنشآت،
متوافق مع متطلّبات هيئة الزكاة والضريبة والدخل ونظام العمل السعودي.

يُستخدم داخلياً، ويُباع اشتراكاً للعملاء من لوحة منصّة مستقلّة.

---

## ما يفعله

| الموديول | ما فيه |
|---|---|
| **المحاسبة** | شجرة حسابات سعودية، قيد مزدوج بمحرّك واحد لا باب خلفي له، سنوات وفترات مالية بقفل، ميزان مراجعة، قائمة دخل، مركز مالي، أستاذ مساعد، أعمار ذمم، إقرار ضريبة القيمة المضافة |
| **الفوترة الإلكترونية** | UBL 2.1، توقيع XAdES، سلسلة تجزئة، رمز QR بصيغة TLV، مولّد CSR، عميل واجهات الهيئة (إجازة وإبلاغ) |
| **المبيعات** | عملاء، فواتير ضريبية ومبسطة، إشعارات دائنة ومدينة، ترحيل تلقائي |
| **المشتريات** | موردون، أوامر شراء، استلام بضاعة، فواتير موردين، منع الإدخال المكرّر |
| **الخزينة** | حسابات بنكية وصناديق، سندات قبض وصرف، تخصيص متعدّد، دفعات مقدمة |
| **المخزون** | أصناف ومستودعات، متوسط مرجّح، تكلفة بضاعة مباعة، تسويات جرد، تحويلات، مطابقة |
| **الموارد البشرية** | موظفون، تأمينات اجتماعية، مسيّر رواتب بثلاث مراحل، إجازات، حضور، مكافأة نهاية الخدمة |
| **المشاريع** | مشاريع ومهام، ساعات عمل، ربحية قبل تكلفة الساعات وبعدها، إيراد غير مفوتَر |
| **المنصة** | إنشاء منشآت العملاء، باقات، اشتراكات، إيقاف وحذف |

## القرارات التي يقوم عليها

**العزل ينزل إلى قاعدة البيانات.** كل جدول يحمل `tenantId` عليه سياسة
Row-Level Security بـ`FORCE`. استعلامٌ نُسي فيه شرط المنشأة يعود بصفر صفوف
لا بدفاتر عميل آخر. تسعة اختبارات تحاول الاختراق عمداً — بالمعرّف،
بالتعديل، بالحذف، وبلا سياق أصلاً — وكلها تُردّ.

> **الدور الذي يتصل به التطبيق يجب ألّا يكون SUPERUSER ولا يحمل BYPASSRLS.**
> Postgres يعفيهما من السياسات إعفاءً تاماً: تبقى معرَّفةً ولا تُطبَّق،
> فيصير كل عملاء المنصة في دفتر واحد ولا شيء في الشاشة يشي بذلك.
> `scripts/apply-rls.ts` يرفض التشغيل بدورٍ كهذا.

**لا حركة بلا قيد.** لا الفاتورة ولا السند ولا الرواتب تكتب في سطور
الأستاذ. كلٌّ منها يبني قيداً ويناوله `postEntry`، فتُفرض عليه القواعد
نفسها: التوازن، ومنع الترحيل على حساب تجميعي، والفترة المفتوحة، ورفض
السالب، ومنع الترحيل مرّتين. والتصحيح بقيدٍ عاكس لا بحذف.

**المال `Decimal` لا `Float`** في كل عمود ودالة. جمع ٠٫١ و٠٫٢ في الفاصلة
العائمة لا يساوي ٠٫٣، وميزانٌ يختلّ بهللة ميزانٌ مرفوض.

**النسب التنظيمية معطيات لا ثوابت.** نسب التأمينات تتغيّر بقرار، ونظامٌ
يدفنها في الكود يجبر كل عميل على انتظار تحديثٍ برمجي.

## التشغيل محلياً

### المتطلّبات
Node 22 فأحدث · PostgreSQL 14 فأحدث

### قاعدة البيانات

```bash
# أنشئ الدور وقاعدة البيانات — والدور ليس سوبريوزر بقصد
sudo -u postgres psql <<'SQL'
CREATE ROLE erp WITH LOGIN PASSWORD 'erp' NOSUPERUSER NOBYPASSRLS;
CREATE DATABASE erp OWNER erp;
SQL
```

### الإعداد

```bash
cd erp
npm install
cp .env.example .env      # ثم عدّل القيم
npm run db:push           # المخطط + سياسات العزل
npm run seed:plans        # باقات الاشتراك
npm run seed              # منشأة تجريبية بدورة سنة كاملة
npm run dev               # http://localhost:3100
```

الدخول بعد البذور:

| الدور | البريد | كلمة المرور |
|---|---|---|
| مالك المنصة والمنشأة | `admin@businesspartner.sa` | `BP-erp-2026` |
| محاسب (صلاحيات أضيق) | `accountant@businesspartner.sa` | `BP-erp-2026` |

## الاختبارات

```bash
npm test          # ١٠٨ اختبار وحدة وتكامل على قاعدة حقيقية
npm run health    # فحص سلامة الدفاتر
npm run build && npm start &
npm run e2e       # اختبار دخان بمتصفّح حقيقي
```

`npm test` يغطّي:

| الملف | ما يثبته |
|---|---|
| `isolation` | لا تسريب بين المنشآت — قراءةً وكتابةً وتعديلاً وحذفاً وبلا سياق |
| `accounting` | التوازن، والحساب التجميعي، والسالب، والفترة المقفلة، والترحيل المكرّر، والعكس |
| `zatca-tlv` | حالة الاختبار الرسمية للهيئة تُنتج الرمز المنشور حرفاً بحرف |
| `zatca-pipeline` | حذف العناصر الثلاثة، وثبات التجزئة بعد الحقن، والتحقق من التوقيع |
| `sales-purchase` | أثر كل مستند في الأستاذ حساباً حساباً، والإقرار الضريبي |
| `inventory` | المتوسط المرجّح، ومنع السالب، ومطابقة الأستاذ للمستودع |
| `hr-payroll` | التأمينات، ومكافأة نهاية الخدمة بحالاتها، والمسيّر |
| `projects` | الربحية، وتكلفة الساعات، والإيراد غير المفوتَر |

`npm run health` يسأل ما لا يسأل عنه أي تقرير مالي — لأنه سؤالٌ عن التقارير
نفسها: هل يتوازن المركز؟ وهل كل قيد متزن في سطوره؟ وهل المخزون يطابق
حركاته؟ وهل ثمّة حساب خصومٍ برصيد مدين (علامةُ صرفٍ سبق استحقاقه)؟

## البنية

```
erp/
├─ prisma/schema.prisma      المخطط — ٤٩ جدولاً، ٤٥ منها معزول بـRLS
├─ scripts/apply-rls.ts      مولّد سياسات العزل + حارس الدور
├─ scripts/health-check.ts   فحص سلامة الدفاتر
├─ src/lib/
│  ├─ db.ts                  عميل القاعدة و`withTenant` — لا وصول خارجه
│  ├─ money.ts               الحساب المالي بـDecimal
│  ├─ rbac.ts                الصلاحيات وأدوار النظام الستة
│  ├─ accounting/            المحرّك والتقارير والفترات والترقيم
│  ├─ zatca/                 TLV، DER، CSR، UBL، تجزئة، توقيع، عميل الواجهات
│  ├─ sales|purchasing|treasury|inventory|hr|projects/
│  └─ provisioning.ts        تجهيز منشأة جديدة وحذفها
├─ src/app/(app)/            لوحة المنشأة — ٢٨ شاشة
├─ src/app/(platform)/       لوحة المنصة — إدارة اشتراكات العملاء
└─ e2e/smoke.mjs             اختبار دخان بمتصفّح حقيقي
```
